## 배경

저장소에 에이전트 작업 지침과 `docs/` 기준 문서가 없었다. 구현 전에 명세를 작성하고, 구현 판단과 검증을 명세에 연결하며, 완료 후 문서를 실제 코드와 동기화하는 SDD 절차가 필요하다. 여행 추천 AI의 데이터·알고리즘·평가·안전 원칙도 코드와 분리된 기준 문서로 찾아볼 수 있어야 한다.

## 목표

- 저장소 루트에 Codex가 읽을 `AGENTS.md`를 둔다.
- 모든 구현 변경에 번호가 있는 SPEC을 적용한다.
- 필요한 문서만 선택적으로 읽을 수 있는 색인을 제공한다.
- 현재 구현과 미구현 추천 목표 구조를 구분해 문서화한다.
- 구현 완료 시 SPEC과 기준 문서를 동기화하는 완료 조건을 정의한다.

## 비목표

- 추천 엔진 또는 추천 API 구현
- 추천 점수 가중치 확정
- 기존 TourAPI 수집기와 지도 UI 동작 변경
- 기존 루트 문서의 이동 또는 재작성

## 요구사항

- `REQ-001`: `AGENTS.md`는 작업 전 관련 SPEC을 찾거나 생성하도록 지시해야 한다.
- `REQ-002`: 새 SPEC은 `docs/spec_NNN.md` 형식과 재사용하지 않는 순번을 사용해야 한다.
- `REQ-003`: 구현 완료 조건에 테스트 결과, 실제 코드 경로, 설계 차이, 기준 문서 동기화가 포함되어야 한다.
- `REQ-004`: `docs/README.md`는 SPEC과 기준 문서의 읽기 경로를 제공해야 한다.
- `REQ-005`: 현재 데이터 파이프라인과 지도 UI를 구현된 상태로 문서화해야 한다.
- `REQ-006`: 추천 파이프라인, 데이터 계약, 평가, 안전 원칙은 목표 설계이며 미구현임을 표시해야 한다.
- `REQ-007`: 문서 로딩으로 인한 토큰 낭비를 줄이기 위해 관련 문서만 읽도록 지시해야 한다.
- `REQ-008`: 프로젝트의 루트 `README.md`에서 문서 색인을 찾을 수 있어야 한다.

## 설계

`AGENTS.md`에는 반복 적용할 작업 규칙과 도메인 불변조건만 둔다. `docs/README.md`는 짧은 색인과 상태를 제공한다. 개별 변경은 SPEC에 기록하고, 여러 변경에서 계속 유효한 현재 설계는 별도의 기준 문서에서 관리한다.

활성 SPEC이 기존 기준 문서와 충돌하면 활성 SPEC이 목표 동작을 정의한다. 구현 완료 시 기준 문서를 갱신해 충돌을 해소한다.
