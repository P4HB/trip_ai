# SPEC-087: KAIST 1단계 제출 산출물과 로컬 자료 제외

- 상태: Implemented
- 작성일: 2026-09-29
- 최종 수정일: 2026-09-29
- 관련 이슈: 사용자 요청 — 최신 코드 반영, 강의 기반 제출용 Spec·비즈니스 프로세스 작성, 교육자료 Git 제외
- 관련 문서: [문서 색인](README.md), [사업 제안](business_model_and_social_impact.md)
- 관련 코드: `.gitignore` (제품 실행 코드 변경 없음)
- 선행 SPEC: SPEC-001

## 배경

개발 변경 이력 SPEC은 제출용 사업·앱 기획 문서로 읽기 어렵다. 로컬 `kaist_app/`의 강의·양식·예제를 근거로 독립된 1단계 제출본을 작성한다. 원격 최신 코드와 로컬 문서가 SPEC-083·084 번호를 중복 사용하여 최신 코드 병합 시 문서 보존 및 참조 복구가 필요하다.

## 목표

- L01·L02 앱 기획 및 초기 사업전략 강의 내용을 반영한 독립 Markdown 제출본 작성.
- 문제 원인에서 가치·사업전략·사용자 흐름으로 연결되는 편집 가능한 draw.io 프로세스 작성.
- 교육자료와 제출 산출물이 저장소에 추적되지 않도록 설정.

## 비목표

- 제품 기능 구현·배포, 실제 고객 접촉, 계약 체결, 실증 결과 창작.
- 강의 원본이나 예제 원문을 Git에 등록하거나 기존 개발 SPEC을 제출본으로 합치기.

## 요구사항

- REQ-001: 원격 최신 코드를 반영하고 기존 로컬 작업을 보존한다. 충돌한 로컬 SPEC-083·084는 SPEC-085·086으로 이동하고 관련 로컬 참조를 갱신한다.
- REQ-002: 강의·예제에서 요구하는 문제 정의, 사업 전략, 고객·가치, 기능·데이터·운영을 독립 Markdown에 반영한다. 사실·설계 결정·가설·검증 계획을 구분한다.
- REQ-003: Weakness → Private Problem → Side Effects → Social Problem의 조건과 인과를 분석하고 해결 가능한 원인과 솔루션을 연결한다.
- REQ-004: draw.io 원본에 필수 Level 1 상호작용과 핵심 Level 2 예외 처리를 표현하고 제출 Spec과 ID로 연결한다.
- REQ-005: `/kaist_app/` 전체를 Git에서 제외하며 원본 자료와 제출물을 보존한다.
- REQ-006: 원본 도면을 실제 draw.io 도구로 열어 가독성과 편집 구조를 확인한다. PDF를 추가 제공하면 렌더링을 확인한다.

## 입력과 출력

- 입력: `kaist_app/LL.강연자료/`의 강의 PDF, 예제 Markdown·draw.io·사업전략 자료, 저장소의 확인 가능한 구현.
- 출력: `kaist_app/제출용/`의 독립 Spec Markdown, draw.io 원본, 선택적 PDF 및 사업전략 보완 문서.
- 기준일: 2026-09-29, Asia/Seoul. 강의 번호·파일명의 차이는 내용 기준으로 출처에 명시한다.

## 설계

제출본은 한 사업 아이디어를 설명하는 문서로 새로 구성한다. 개발 SPEC 번호 체계와 분리하며, 미래 기능은 계획/미구현으로 표시한다. 사용자 요청 범위는 승인된 산출물 요구사항으로 보되 가격·시장성·성과 수치는 검증 전 가설로 작성한다. 자료 복제는 교육 목적의 로컬 작업 폴더에 한정한다.

## 예외와 폴백

- 전용 플러그인이 없으면 draw.io 네이티브 XML을 작성하고 실제 draw.io 편집기에서 검증한다.
- L03 명칭이 없으면 제목·본문상 초기 사업전략 자료를 사용하고 번호 차이를 기록한다.
- 외부 서비스가 없거나 미확인 데이터인 경우 보장된 기능으로 표현하지 않는다.

## 영향 범위

- 변경 예정 파일: `.gitignore`, `docs/README.md`, `docs/spec_087.md`, 번호 충돌 복구에 필요한 로컬 문서와 주석, `kaist_app/` 산출물.
- 데이터 마이그레이션: 없음.
- 호환성 영향: 제품 동작 변경 없음. 기존 로컬 문서의 SPEC 번호만 충돌 해소.
- 보안·개인정보 영향: 비밀키·원본 위치 이력·평가자 개인정보를 제출물에 포함하지 않는다.

## 승인 기준

- AC-001: HEAD가 확인한 origin/main을 포함하고 기존 문서 내용이 보존된다 (REQ-001).
- AC-002: 제출 Spec에 강의 반영표, 인과 분석, 초기 사업전략, 기능 요구사항과 승인 기준이 있다 (REQ-002·003).
- AC-003: draw.io Level 1에 고객·서비스·운영·지급자 상호작용이 있고 핵심 예외와 Spec ID가 일치한다 (REQ-004).
- AC-004: `git ls-files kaist_app`가 비어 있고 `git check-ignore`가 원본 및 산출물을 제외한다 (REQ-005).
- AC-005: draw.io 편집기 및 제공 PDF의 시각 검증에서 잘림·겹침·깨진 한글이 없다 (REQ-006).

## 구현 결과

- `origin/main`의 최신 확인 commit `bacc5f6`을 fast-forward 반영했다. 기존 로컬 문서 4개를 stash `b13b9966e54c6ff01c53652ea4e17268fe94ae8b`에 보존하고 복원했다. 원격 SPEC-083·084와 충돌한 기존 로컬 문서는 SPEC-085·086으로 이동했고 `docs/README.md`, `docs/data_contracts.md`, `docs/kakao_restaurant_collection.md`, 음식점 실행기·시험 파일의 문서 참조/주석을 갱신했다. 원격 SPEC-083·084의 내용은 변경하지 않았다.
- `.gitignore`에 `/kaist_app/`를 추가했다. 기존 추적 파일은 없어 인덱스에서 제거할 파일은 없었다.
- `kaist_app/제출용/01_Trip_AI_1단계_Spec.md`: 문제 인과·Surface, 5W1H, 사용자/지불자, 초기 B2B 숙박 실증 가설, 가치사슬·STP·4P·시장 범위, 구현 경계, 10개 기능·6개 비기능 요구사항과 10개 승인 기준, 논리 데이터·시험·강의 반영표.
- `kaist_app/제출용/02_Trip_AI_Business_Process.drawio`: 이미지가 아닌 네이티브 도형·연결선으로 작성한 L1 1장과 L2 2장, 총 54개 연결선. 실제 draw.io 편집기에서 3개 페이지를 열어 확인했다.
- `kaist_app/제출용/02_Trip_AI_Business_Process.pdf`: 동일 도면 정의로 생성한 3쪽 PDF. 한글 글꼴 포함, 페이지별 북마크. Poppler로 렌더링해 전 페이지를 확인하고 화살표 문구 겹침을 수정했다.
- `kaist_app/제출용/03_초기사업전략_검증계획.md`: 진입안 비교, 인터뷰 질문, 교차 비교 실험, 실증 원가 시나리오와 중단 기준을 보완했다.
- `kaist_app/제출용/00_제출안내.md`: 필수/선택 제출 파일과 읽는 방법을 정리했다.

검증 기록과 재생성 도구는 제외된 `kaist_app/_work/`에 보관했다. 실행: `python kaist_app/_work/build_process.py`, `python kaist_app/_work/render_process_pdf.py`, `python kaist_app/_work/validate_deliverables.py` (PDF 도구는 번들 Python 사용). 관련 변경의 `git diff --check` 통과. 제품 실행 코드를 바꾸지 않아 추천·지도 데이터 재생성 및 제품 기능 시험은 수행하지 않았다.

## 설계와 달라진 점

- 자료에 L03 파일이 없어 본문 주제가 일치하는 L04 초기 사업전략 설계 PDF를 사용하고 제출본에 명시했다.
- 전용 draw.io 플러그인 대신 네이티브 XML을 작성하고 draw.io 웹 편집기의 공식 raw-diagram 불러오기 방식으로 검증했다. 파일 선택기 자동화가 동작하지 않아 같은 원본을 공식 URL hash 형식으로 로드했다. PDF는 온라인 변환 서버 대신 같은 도면 정의를 로컬에서 렌더링했다.

## 알려진 제한

- 사업 성과·시장성·가격 수용성은 이 작업에서 검증하지 않았다. 제출본은 사업 가설과 후속 검증 기준을 제시한다.
- draw.io 편집 후 PDF의 자동 동기화는 없다. 동일 정의의 생성 도구를 함께 수정하거나 draw.io에서 PDF를 다시 내보내야 한다.
- `kaist_app/`는 Git에서 제외되므로 별도 보관·제출해야 한다. 강의 원문은 재배포하지 않았다.
