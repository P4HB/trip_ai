# SPEC-074: 장소 평가 완료 버튼과 추천 목록 완료 표시

- 상태: Implemented
- 작성일: 2026-09-03
- 최종 수정일: 2026-09-03
- 관련 이슈: 사용자 요청 — 사진 아래 안내 삭제, 점수 필수·의견 선택 완료 버튼, 추천 화면 완료 체크
- 관련 문서: [시스템 아키텍처](architecture.md), [SPEC-073](spec_073.md), [SPEC-060](spec_060.md)

## 배경

모바일 평가 사진 아래 장소와 무관한 입력 동기화·저장 안내가 있다. 점수·의견은 자동 저장하지만 명시적으로 평가를 마치거나 목록에서 완료 여부를 확인할 수 없다.

## 목표

사진 아래 중복 안내를 삭제하고, 점수 선택 후 완료할 수 있게 하며 추천·일정 카드에 완료 체크와 점수를 표시한다.

## 비목표

장소 설명·사진·방문 후기 삭제, 추천 알고리즘 및 서버 API·DB 스키마 변경.

## 요구사항

- `REQ-7401`: 모바일 평가 사진 바로 아래 자동 저장·동기화 안내 문단을 삭제한다.
- `REQ-7402`: 유효한 1~5점이 없으면 완료 버튼을 숨기고 완료 처리를 차단한다. 점수는 필수, 최대 300자 의견은 선택이다.
- `REQ-7403`: 완료 버튼은 현재 장소를 완료 상태로 바꾸고 모바일 평가 창을 닫아 기존 추천 화면 위치·포커스로 돌아간다.
- `REQ-7404`: 추천·일정 카드에서 미평가, 점수 입력 후 미완료, 완료를 텍스트로 구분하며 완료에는 체크와 점수를 표시한다. 같은 장소는 즉시 동기화한다.
- `REQ-7405`: 완료 뒤 점수·의견을 수정하면 미완료로 돌아간다. 단순 재열기·닫기는 완료 상태를 보존하고 새 추천 조건으로 초기화하면 완료 상태도 초기화한다.
- `REQ-7406`: 기존 자동 저장·이름 대기·재시도 정책을 유지하고 완료 시 대기 중 의견 저장을 즉시 예약한다. 입력 완료 표시와 서버 저장 성공을 구분한다.

## 입력과 출력

점수는 정수 1..5 또는 null, 의견은 최대 300자 문자열이다. 브라우저 장소별 피드백에 boolean `completed`를 추가하며 서버 v3 payload에는 보내지 않는다.

## 설계

공통 피드백 컴포넌트에 완료 버튼을 추가하고 placeId 기반 동기화 함수로 버튼·카드 배지를 갱신한다. 상태는 `미평가 → 점수 입력 → 완료`, 완료 후 편집 시 `점수 입력`이다. 모바일 지도 상세 완료 시 상세를 닫고 추천 결과를 표시하며 인라인 카드 완료는 위치를 유지한다.

## 예외와 폴백

의견만 입력하면 완료 불가다. 서버 오류나 이름 미입력은 기존 저장 상태로 알린다. 새로고침 시 브라우저 메모리가 초기화되는 정책을 유지한다.

## 승인 기준

- `AC-7401`: 사진 아래 안내가 사라지고 사진·장소 설명·방문 후기는 유지된다.
- `AC-7402`: 의견만 입력하면 완료 버튼이 없고 점수만 입력하면 완료할 수 있다.
- `AC-7403`: 완료 후 창이 닫히고 추천·일정 동일 장소에 체크와 점수가 보인다.
- `AC-7404`: 재열기, 수정 후 재완료, 새 추천 초기화가 요구 상태 전이를 따른다.
- `AC-7405`: 기존 자동 저장 계약·구문 검사가 통과하며 그래프가 갱신된다.

## 구현 결과

- 공통 평가 컴포넌트에 점수 유효성 검사와 완료 버튼을 추가했다. 점수·의견 변경은 `completed: false`, 완료는 `true`로 전환한다.
- 추천·일정 카드에 `미평가`, `N점 · 완료 전`, `✓ 평가 완료 · N점` 배지를 추가하고 동일 장소를 즉시 동기화했다.
- 사진 아래 입력 동기화·자동 저장 문단을 삭제했다. 사진·설명·후기는 유지했다.
- 완료 시 기존 자동 저장을 즉시 예약하며 모바일 modal은 닫고 포커스를 복원한다. 모바일 지도 상세 완료는 추천 결과로 돌아간다.
- `map-ui/index.html`의 app·styles 버전도 갱신했다.
- `node --check map-ui/app.js`, `node scripts/validate_ccu_mmr_dashboard.cjs`: 통과.
- `node scripts/test_feedback_completion.cjs`: 실제 Chromium 390×844·1440×1000에서 점수 필수, 의견 생략, 완료·복귀 위치, 추천·일정 배지 동기화, 재열기·ESC 보존, 편집 후 재완료, 이름 대기, v3 payload 호환성, 새 조건 초기화 통과. 가로 넘침·pageerror 없음.
- 테스트는 Playwright를 사용한다. 프로젝트에 설치된 Playwright 또는 실행 환경의 `NODE_PATH`를 사용하고, 필요하면 `FEEDBACK_TEST_CHROMIUM`으로 Chromium 실행 파일을 지정한다. 로컬 서버에 실제 앱·데이터를 로드하고 추천 입력 준비만 테스트 훅으로 주입한다. 외부 이미지·후기·저장 요청은 fixture로 격리하므로 운영 서버에 평가를 전송하지 않는다.
- `artifacts/feedback-completion/completed.png`, `dialog.png`를 확인해 모바일 완료 체크와 버튼 배치·문구 삭제를 시각 검증했다.
- `graphify update . --no-cluster`: 통과, 4,068 nodes·6,444 edges로 코드 그래프 갱신. `git diff --check`도 통과.
