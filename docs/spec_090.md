## 배경

제출 Spec v1.2와 프로세스는 강의 구조에 부합하나 유사 서비스의 실제 근거, 다음 검증의 일정·자원, 비기능 요구사항의 개별 추적, 최종 출시 결정 역할이 부족하다. 사용자는 해당 검토 결과의 보완을 요청했다. 사업은 지역에 한정하지 않으며 현재 MVP만 제주라는 범위와 산출물 1·2만 작성한다는 범위를 유지한다.

## 목표

- 공식 자료로 유사 서비스의 이용자·지불자·기능·과금과 비교의 한계를 정리한다.
- 다음 검증을 실행 가능한 책임 역할·기간 가안·필요 자원·완료 증거로 연결한다.
- 기존 NFR별 우선순위·적용 흐름·검증 방법과 출시 결정 절차를 명시한다.
- Spec, 프로세스 원본·PDF, 제출 안내와 내부 대조 기록을 동기화한다.

## 비목표

- 실제 구매자 인터뷰·영업 메시지 발송·계약·지출·제품 배포.
- 미확인 매출·수익·팀원·예산·고객·검증 결과 창작.
- 산출물 3·4·5 제작, 제품 코드·추천 동작·데이터 변경.

## 요구사항

- REQ-001: 최소 3개 관련 서비스의 공식 자료를 확인하고 출처 URL·확인일·기능·과금 단위·범위를 제시한다. 자료가 없는 가격·이익·구매 반응은 미확인으로 남긴다. Trip AI의 차이는 검증할 가설로 표시한다.
- REQ-002: 구매자 조사에서 수집할 근거와 현재 확보 상태를 분리한다. 다음 검증의 책임 역할·소요기간 가안·필요 자원·완료 증거·진행 결정을 작성하되 기존 임의 예산을 확정값으로 복원하지 않는다.
- REQ-003: 기존 NFR-001~006을 개별 우선순위·Actor/BP·화면/처리/기록·시험 ID·판정 기준에 연결한다. 계획된 시험을 통과한 것으로 표현하지 않는다.
- REQ-004: 제품 책임자의 확인, 운영 준비 확인, 사업 책임자의 최종 출시 결정과 보류·재확인 흐름을 정한다. OPS 내 역할로 모델링하며 기존 Actor를 불필요하게 늘리지 않는다. 고객의 계약상 검수와 구분한다.
- REQ-005: Spec v1.3, draw.io와 PDF의 관련 BP-02 흐름·참조를 동기화한다. 제주 MVP, 기존 요구사항 ID, 산출물 1·2 범위와 Git 제외 상태를 유지한다.

## 입력과 출력

- 입력: 제출 Spec v1.2, L01·L02 원문·재검토 기록, 기존 도면 정의, 공식 웹 공개 자료.
- 출력: 제출 Spec v1.3, 동기화한 도면 원본·PDF와 동반 Markdown. 조사 근거와 검증 결과는 `kaist_app/_work/`에 보관한다.
- 날짜: 2026-09-29, Asia/Seoul. 외화 가격은 출처 표시 통화를 그대로 사용하고 환율 환산하지 않는다.

## 설계

12장과 기존 제품 REQ/AC/NFR ID를 유지한다. §3.4에 실제 서비스 비교를 추가하고 §9~10에서 구매 조사와 다음 검증·출시 판단을 구체화한다. §7의 NFR 공통 행을 개별 행·시험 기준으로 바꾼다. L1 BP-02와 L2-B의 접점 공개 전 흐름에 출시 확인을 반영한다. 팀원의 실명 대신 현재 OPS 내 사업·제품·운영 책임 역할을 사용하고 실제 배정은 착수 전 확정으로 남긴다.

## 예외와 폴백

- 공식 페이지에서 가격·대상 범위가 확인되지 않으면 임의 견적을 대신 넣지 않는다.
- 실제 가용 자원을 확인하지 못하므로 상대 일정과 가안을 사용하고 착수 시 재산정 조건을 명시한다.
- P0 또는 필수 NFR 검증이 실패하거나 미실행이면 해당 실증 공개를 보류한다. 기존 정상본은 보존한다.

## 구현 결과

- 제출 Spec을 v1.3으로 갱신했다. 기존 12장과 REQ-001~010·AC-001~010·NFR-001~006을 유지했다.
- §3.4에 트리플, Wanderlog, Mindtrip for Business의 공식 자료 비교를 넣었다. 확인일과 직접 URL을 행별로 연결했다. Wanderlog의 2024년 공식 가격 안내는 현재 결제가로 취급하지 않았으며, 공개되지 않은 수수료·계약금액·서비스별 이익을 미확인으로 표시했다. 실제 경쟁 우위는 검증 가설로 남겼다.
- §9.4에 구매자 업무·현재 대안·결정권·가격·지속 이용 증거의 확보 상태와 수집 방법을 추가했다. 실제 인터뷰·회신·유료 계약을 확보했다고 주장하지 않는다.
- §10.2에 D0 준비 후 D+1~10의 일정 가안, 책임 역할·자원·비용 확정·완료 증거를 연결했다. 실제 팀원·가용 시간·예산은 D0에 결정한다. 기존 임의 예산·실증 수치는 보완 문서에 유지했다.
- §7.2~7.3에서 NFR 6개를 각각 우선순위·Actor/BP·화면/운영·데이터·TN-01~06 시험과 판정 기준에 연결했다. §10.3에는 제품·운영의 사전 확인, 사업 책임자의 최종 출시 결정과 보류·재확인을 정했다. 사전 검증과 최종 출시 기록 작성 시점을 구분했다.
- L1 BP-02와 L2-B 도면의 공개 전 확인·출시 결정·미통과 분기를 동기화했다. 편집 가능한 draw.io 3장·55개 연결선과 같은 정의로 만든 PDF 3쪽을 유지했다. 제출 안내·사업전략 보완·평가 대조·이전 재검토 기록도 동기화했다.

## 설계와 달라진 점

새 Actor나 페이지를 추가하지 않고 기존 OPS 레인과 BP-02의 분기를 사용했다. L2-B의 데이터 검수 판단을 제품·운영 증거를 종합하는 출시 판단으로 확장하고, 정보 오류만 원천 제공자 확인으로 연결하도록 설명했다. 외부 자료의 최신 결제금액을 확인하지 못한 부분은 과거 자료와 미확인 상태를 구분해 기재했다.

## 알려진 제한

공식 서비스 소개는 공급사의 설명이며 실제 성능·수익·국내 도입 적합성의 검증이 아니다. 구매자 현장 조사와 실제 제품 출시 시험은 이번 문서 작업으로 수행되지 않는다.
