## 배경

사용자는 관광지용 코드를 그대로 두고 같은 구조의 제주 음식점 수집과 실제 실행을 요청했다. 두 원본 파일은 현재 로컬 checkout에는 없고 원격 저장소에서 확인했다. 원본은 핵심 Selenium 모듈과 43개 읍·면·동 배치 실행기로 구성되며 장소별 기본 리뷰 수는 5다. 원본 검색 목록 확장 시 첫 장소가 같으면 페이지 전환을 잘못 실패로 판단할 수 있고, 검색 키워드만으로 행정구역·업종을 보장하지 못한다.

## 목표

- 원본 파일을 변경하지 않고 음식점 전용 모듈과 실행기를 추가한다.
- 제주 전역 공개 검색에서 찾을 수 있는 음식점을 중복 제거해 모으고 재개 가능한 상태로 저장한다.
- 사용자 확정: 카페·제과점 제외, 평점 하한 없이 음식점 수집.
- 장소와 리뷰의 출처, 확인 시각, 검색 진행률 및 누락 가능성을 기록한다.

## 비목표

- 검색 서비스에 미노출된 모든 업소의 존재나 검색의 전수성을 보증
- 기존 관광지 데이터, 지도 UI, 추천 DB 변경, 공개 배포
- 로그인·CAPTCHA·접근 제한 우회, 작성자 프로필 수집
- 평점으로 맛집을 판정하거나 추천 점수에 반영

## 요구사항

- `REQ-8301`: 원본 두 파일은 그대로 유지하며 새 파일 두 개에 핵심/배치 구조를 따른다.
- `REQ-8302`: 기존 43개 제주 행정구역을 사용하고 넓은 음식점 검색과 하위 음식 유형 검색으로 노출 상한 누락을 줄인다. 주소가 제주가 아니거나 카페·제과점인 장소를 제외하고 업종 불명은 검토 대상으로 분리한다.
- `REQ-8303`: 장소 ID로 중복 제거하고 검색어별 결과·실패·검색 상한/정체 상태를 기록한다. 시간 초과를 완료로 기록하지 않는다.
- `REQ-8304`: 인벤토리·상세·리뷰 수집에 요청 간 대기, 원자적 체크포인트와 재개 기능을 제공한다. 선택 가능한 병행 모드는 검색 1개와 상세 1개 또는 검색 완료 후 상세 2개로 최대 브라우저 2개를 유지하며 DB와 CSV 저장은 주 실행 흐름 하나가 담당한다.
- `REQ-8305`: 장소·리뷰·요약 CSV, SQLite 상태, manifest를 독립 날짜별 restaurants 폴더에 기록한다. 작성자 표시명은 새 결과에 저장하지 않는다.
- `REQ-8306`: 리뷰 개수는 CLI에서 설정하며 기본 5건은 원본과 동일하다. 0건 또는 전체 수집 요청도 구별한다. 사용자 답변이 오면 본 SPEC에 반영한다.
- `REQ-8307`: 실제 작은 표본으로 셀렉터·지역·업종·리뷰를 확인한 뒤 전체 실행하며, 진행 중/일부 실패/완료 및 전수성 미보장을 정직하게 구별한다.
- `REQ-8308`: 사용자 추가 요청에 따라 장소별 방문자 후기 총수(`visitor_review_count`)와 블로그 리뷰 총수(`blog_review_count`)를 출처의 표시값으로 저장한다. 실제 저장한 후기 본문 수(`collected_review_count`, 기본 최대 5건)와 구분하며, 미확인 개수는 빈 값으로 유지한다.
- `REQ-8309`: 사용자 추가 요청에 따라 카카오맵 상세의 공개 영업시간·정기휴무·브레이크타임·라스트오더를 원문 그대로 수집한다. 원문 출처, 확인 시각, 수집 상태를 함께 저장하고 미제공과 로딩/파싱 실패를 구별한다. 요일이나 시간을 근거 없이 추정·보완하지 않는다.
- `REQ-8310`: 이미 발견한 모든 음식점을 상세 방문 대상으로 유지해 운영시간을 보완한다. 이미 상세 완료한 구형 레코드도 운영시간 확인 기록이 없으면 재처리한다. 기존 인벤토리·리뷰를 보존하며 안전하게 저장 후 실행기를 갱신·재개한다.
- `REQ-8311`: 속도 개선 모드는 남은 검색 범위를 줄이지 않고 상세 수집을 검색과 함께 시작한다. 각 작업의 브라우저를 배치 내에서 재사용하고 화면 로딩 대기와 실패 시 대기를 유지한다. 저장을 확인한 뒤 다음 페이지로 진행하며 접근 제한 또는 연속 실패 시 두 작업을 함께 중단한다.
- `REQ-8312`: 매장주 요청에 따른 후기 미제공은 오류나 후기 0건과 구별해 `review_status=not_provided`로 기록하고 숨겨진 DOM의 기본 숫자는 리뷰 총수로 사용하지 않는다. 영업시간 미등록 안내가 기본 정보 영역에만 있어도 명시적 미등록으로 기록한다. 상세 미방문→실패 재시도→완료 장소의 영업시간 보완 순서로 처리하고 실제 로딩 오류는 실패로 남긴다.

## 입력과 출력

- 입력: 지역·음식 유형 검색어, 최대 리뷰 수, 대기·배치 설정. API 키 불필요.
- 출력: `data/kakao/jeju/YYYY-MM-DD/restaurants/`의 `places.csv`, `place_review_summary.csv`, `reviews.csv`, `business_hours.csv`, `collection.sqlite3`, `manifest.json`, `queries.csv`, `excluded_places.csv`.
- 시각은 `+09:00` ISO 8601, CSV UTF-8 BOM. 확인되지 않은 값은 빈 값/null이며 0으로 추측하지 않는다. 좌표는 수집 가능한 근거가 없으면 추가하지 않는다.
- 장소 기본 필드는 원본 `Place`를 유지하며 주소, 업종, 발견 검색어, 수집 시각을 추가한다. 후기 필드는 원본 구조를 따르되 reviewer는 제외한다.

## 설계 (구현 진행 중)

1. 기존 Selenium 모듈에서 분리된 음식점 모듈에 DOM 파서·페이지 전환·리뷰 수집 함수를 둔다.
2. 배치 실행기는 지역×검색어 계획을 SQLite에 등록하고 검색 결과·검색 진행 상태를 같은 트랜잭션으로 저장한다.
3. 검색 노출 상한, 불명확한 페이지 종료, 로딩 실패를 manifest에 드러낸다. 실제 한림읍 검색에서 표시 1,337건 중 500건까지만 노출됨을 확인했다. 상한에 걸리면 한식·중식 등 15개 하위 검색을 추가하고 한식·고기 등도 상한에 걸리면 더 세분화한다. 분할표는 실행기의 `REFINEMENTS`가 정본이다. 알려진 분할이 없는 leaf의 상한은 그대로 기록한다.
4. 장소별 후기 저장과 상세 완료 상태를 같은 트랜잭션으로 저장한다. 실패한 장소는 재실행 시 재시도한다.
5. 각 체크포인트에서 CSV와 manifest를 갱신하고 중단 후 같은 출력 폴더에서 재개한다.
6. 운영시간 확장은 기존 장소/리뷰 필드를 보존한 부가 `business_hours` 테이블과 `business_hours.csv`로 저장한다. 먼저 상세 화면에서 실제 DOM을 확인하고 운영시간 영역을 펼쳐 읽는다. 저장은 `status=available|not_provided|unrecognized`, 원문 텍스트, 출처 URL, 확인 시각을 포함한다. 오류는 완료로 표기하지 않는다. 상세·리뷰 단계에서 운영시간을 함께 수집하고, 전체 완료 후 운영시간만 누락된 구형 상세도 다시 방문한다. manifest에 운영시간 확인/기재/미기재/미확인 건수를 구분한다.
7. 실제 리뷰 0건 페이지에는 `.section_review` 대신 `.section_grade`의 후기 작성 안내가 있다. 이 안내는 리뷰가 있는 장소에도 존재하므로 목록 관찰값 0, 리뷰 섹션 부재, 후기 작성 안내를 모두 확인할 때만 빈 상태로 해석한다. 상세 로딩은 장소 기본 정보 영역으로 확인한다. `#review`로 바로 진입하면 상단 운영시간 DOM이 지연 로딩되어 없어질 수 있어 `?openhour=1`로 상단 정보를 먼저 저장한 뒤 리뷰 위치로 이동한다. 운영시간은 리뷰 로딩 전에 별도 저장해 이후 후기 오류에도 보존한다. `--place-id` 반복 인수로 이미 저장된 특정 식당만 검증/재처리할 수 있고 전체 검색 계획은 지우지 않는다.
8. `장소 더보기`가 첫 15곳을 유지한 채 페이지 1의 탐색 버튼만 여는 경우도 실제 확인했다. 목록 변경뿐 아니라 더보기 링크 숨김 + 활성 페이지 1의 전환을 인식하고, 이미 저장한 첫 페이지를 중복 처리하지 않은 채 다음 페이지로 이동한다. 화면 전환 근거가 없는 정체는 계속 실패 처리한다.
9. 속도 개선 구현: `--concurrent`는 검색·상세 전용 실행 흐름을 하나씩 둔다. 브라우저는 각 흐름이 소유하고 SQLite는 주 흐름만 접근한다. 페이지/운영시간 저장 콜백은 큐로 전달하고 저장 성공 응답을 기다린다. 두 작업의 성공·실패·시도 제한·대기는 독립적으로 관리하되 STOP/접근 제한/연속 실패는 전체 실행에 적용한다. CSV 전체 재생성은 완료 작업 배치마다 수행하고 DB는 페이지/장소 단위로 즉시 저장한다. 기본 순차 실행은 호환성을 위해 유지한다.
10. 2026-09-29 보완 구현: 실제 실패 2곳에서 `.desc_noti`의 `매장주 요청으로 후기가 제공되지 않는 장소입니다.`를 확인했다. 이를 명시적 미제공으로 기록하며 방문자 후기 총수는 빈 값으로 둔다. 검색의 숨겨진 `.score.HIDDEN` 내부 `(30)`은 표시값이 아니므로 파서가 제외한다. 기존 값은 해당 장소의 미제공을 상세에서 확인할 때 정정한다. 영업시간은 `.info_operation`이 없어도 `.section_defaultinfo .txt_detail2`의 미등록 안내가 있으면 `not_provided`다. 아직 방문하지 않은 장소가 과거 실패 항목 때문에 대기하지 않도록 처리 순서를 바꿨다. `--concurrent --skip-inventory --detail-workers 2`는 상세 시도 ID와 최대 장소 수를 두 작업이 공유한다. 상세/리뷰 시간 초과에 단계 이름을 붙여 원인을 추적한다.

## 예외와 폴백

- 빈 결과는 명시적 화면 증거가 있을 때만 완료 처리한다.
- 2026-09-22 실제 카카오맵의 `검색 결과가 없어요.` 문구를 확인했다. 기존 `검색결과가 없습니다`/`검색 결과가 없습니다`와 함께 명시적 0건으로 처리한다. 문구가 없고 카드도 없는 로딩 실패는 여전히 실패다.
- 리뷰 0건은 명시적 0건과 로딩 실패를 구별한다.
- 연속 실패/접근 제한은 저장 후 중단하며 성공으로 간주하지 않는다.
- 파일/설정 불일치나 다른 실행의 동일 DB 사용은 오류로 중단한다.

## 영향 범위

- 새 수집기 2개, 범위가 좁은 회귀 테스트, 실행 안내, 본 SPEC·색인·데이터 계약의 링크.
- 기존 DB 마이그레이션 없음. 다른 로컬 변경은 유지한다.
- 공개 후기만 내부 수집하며 작성자명·프로필·사진은 저장하지 않는다. 산출물 공개 배포는 범위 밖이다.

## 승인 기준

- `AC-8301`: 원본 파일 수정 없음, 새 두 스크립트 구문 검사 통과.
- `AC-8302`: 제주 주소/음식점 포함·카페/제과점/비제주 제외 및 알 수 없는 업종 분리가 검증된다.
- `AC-8303`: 목록 확장, 페이지 전환, 정체·실패와 0건 구분, 중복 제거 및 중단 후 재개가 검증된다.
- `AC-8304`: 실제 표본에서 장소와 설정한 리뷰 수집, CSV/DB/manifest 일치가 검증된다.
- `AC-8305`: 전체 실행의 완료 범위·건수·실패·남은 작업과 검색 기반 수집 한계를 기록한다. 전수 수집 성공은 검증 없이 선언하지 않는다.
- `AC-8306`: 실제 저장된 음식점의 CSV·DB에서 방문자/블로그 리뷰 총수를 확인하고, 상세 표본에서 전체 후기 수와 저장한 본문 수가 별도 필드임을 검증한다.
