# SPEC-013: 지도 UI v5 전수 근거 라벨 표시 v1

- 상태: Implemented
- 작성일: 2026-08-12
- 최종 수정일: 2026-08-12
- 관련 요청: 지도에서 장소를 선택했을 때 v5 전수 검토의 라벨 결과가 보여야 한다.
- 관련 문서: [문서 색인](README.md), [시스템 아키텍처](architecture.md), [데이터 계약](data_contracts.md), [SPEC-012](spec_012.md)
- 관련 코드: `scripts/build_map_ui_data.mjs`, `map-ui/`
- 선행 SPEC: SPEC-010, SPEC-012

## 배경

`map-ui`는 TourAPI 장소 기본 정보만 읽어 장소 상세 카드에 라벨을 표시하지 않는다. v5 전수 근거 검토는 1,664개 장소의 24개 라벨과 근거를 별도 JSON으로 보관한다.

## 목표

- 지도 데이터 생성 시 v5 검토 결과를 `contentid`로 장소와 조인한다.
- 지도에서 장소를 선택하면 24개 라벨의 점수·검토 상태를 모두 보여준다.
- 라벨을 선택하면 판단 사유와 연결된 웹 근거 링크를 보여준다.

## 비목표

- 지도에서 v5 라벨을 수정하거나 원본 검수 JSON을 변경하는 기능
- 외부 API/fetch 또는 계정 기반 기능

## 요구사항

- `REQ-1301`: 유효 좌표 지도 장소에 대응하는 v5 라벨은 `contentid`로만 조인한다.
- `REQ-1302`: 장소 상세는 Theme 8개, Environment 2개, Style 8개, 파생 Style 6개를 표시한다.
- `REQ-1303`: 선택 라벨의 값, 상태, 사유, 연결된 HTTPS 근거 링크를 표시한다.
- `REQ-1304`: 정적 데이터 번들만 읽으며 브라우저 fetch를 사용하지 않는다.

## 승인 기준

- `AC-1301`: 생성된 지도 데이터의 v5 라벨 장소 수가 1,664개이고, 각 장소가 24개 라벨을 가진다.
- `AC-1302`: 넥슨컴퓨터박물관(`2472824`)을 지도에서 선택하면 24개 라벨과 `local_embeddedness=0.25`가 보인다.
- `AC-1303`: 선택 라벨에서 기록된 출처 링크를 열 수 있다.
- `AC-1304`: 생성기·지도 앱 구문 검사, 지도 데이터 생성, 로컬 HTTP 200을 통과한다.

## 테스트 계획

| AC-1304 | `node --check scripts/build_map_ui_data.mjs`, `node --check map-ui/app.js`, `Invoke-WebRequest` |

## 구현 결과

구현 완료.

- `scripts/build_map_ui_data.mjs`가 v5 review JSON의 두 저장 형태를 정규화해 지도 장소에 `v5` 객체로 조인한다.
- `map-ui` 장소 상세 카드가 24개 라벨 점수·상태를 표시하고, 항목 클릭 시 판단 사유와 해당 웹 근거 링크를 표시한다.
- 넥슨컴퓨터박물관(`2472824`)이 생성 번들에서 24개 라벨과 `style_evidence.local_embeddedness=0.25`, 출처 2건을 가진 것을 확인했다.
- 지도 번들은 2,153개 유효 좌표 장소와 1,664개 v5 검수 결과를 포함한다. 좌표가 잘못된 영주산(`2704351`)은 기존 정책대로 지도에서 제외된다.
