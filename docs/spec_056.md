- 상태: Implemented
- 작성일: 2026-08-24
- 최종 수정일: 2026-08-24
- 관련 요청: 베타 테스터용 추천 카드에서 ID·MMR·점수 trace·연결 출처 등 내부 정보를 숨기고 상세보기로 옮기며, 장소별 추천 만족도를 입력할 수 있게 한다.
- 관련 문서: [문서 색인](README.md), [시스템 아키텍처](architecture.md), [SPEC-020](spec_020.md)
- 관련 코드: `map-ui/index.html`, `map-ui/styles.css`, `map-ui/app.js`, `map-ui/README.md`, `scripts/validate_ccu_mmr_dashboard.cjs`
- 선행 SPEC: SPEC-020

## 배경

현재 추천 결과 카드는 장소 ID, 관련도 수치, MMR·P·A·M 점수, 웹 조사 출처, seed 확률과 유사도까지 한 화면에 노출한다. 이 정보는 추천 엔진을 검증하는 운영자에게는 필요하지만 베타 테스터가 장소를 판단하는 데에는 방해가 된다. 또한 카드 전체가 하나의 버튼이라 장소 상세 열기와 장소별 만족도 입력을 독립된 행동으로 제공할 수 없다.

## 목표

- 베타 테스터가 먼저 보는 추천 카드에는 장소명, 유형·지역, 간단한 장소 설명과 사람이 읽을 수 있는 추천 이유만 표시한다.
- ID, 내부 점수, 연결 출처, seed·유사도 trace는 카드에서 제거하고 장소 상세보기에서 확인할 수 있게 한다.
- 추천된 장소마다 추천 만족도를 1~5단계로 입력하고 현재 브라우저 세션에서 선택 상태를 확인할 수 있게 한다.
- 추천된 장소마다 최대 300자의 선택형 자유 의견을 작성하고 글자 수와 현재 입력 상태를 확인할 수 있게 한다.
- 시작일·종료일로 생성된 일자별 일정의 각 장소에서도 추천 목록과 같은 만족도·자유 의견을 입력할 수 있게 한다.
- 같은 장소가 추천 목록과 일정에 함께 표시되면 양쪽 입력을 장소 ID 기준으로 즉시 동기화한다.
- 저장·전송 백엔드 없이 향후 피드백 API와 연결할 수 있는 명확한 UI 상태 경계를 만든다.

## 비목표

- 피드백 API, 데이터베이스, 분석 이벤트 또는 Web Storage 구현
- 추천·랭킹·MMR·일정 알고리즘 및 결과 스키마 변경
- 방문 완료 확인 또는 계정별 피드백 이력
- 운영자 전용 인증이나 권한별 화면 분리

## 요구사항

- `REQ-5601`: 추천 카드 기본 화면에서 장소 ID, 관련도·MMR·P/A/M 수치, 연결 출처·확인일, seed 확률과 유사도 수치를 노출하지 않는다.
- `REQ-5602`: 추천 카드에는 순위, 장소명, 유형·지역, 짧은 장소 설명과 수치 없는 추천 이유를 표시한다.
- `REQ-5603`: 각 카드에 명시적인 `상세보기` 버튼을 제공하고 장소 상세 패널에서 ID, 웹 조사 출처·확인일, CCU-MMR 점수 trace와 41개 라벨을 확인할 수 있게 한다.
- `REQ-5604`: 각 추천 장소에 `이 추천, 얼마나 마음에 드나요?` 1~5 만족도 입력을 제공한다. 1은 `전혀 안 끌려요`, 5는 `꼭 가고 싶어요`로 해석한다.
- `REQ-5605`: 만족도 버튼은 `aria-pressed`와 점수별 접근 가능한 이름을 제공하고 선택한 값을 카드 안에서 시각적으로 확인할 수 있게 한다.
- `REQ-5606`: 만족도와 자유 의견은 `placeId -> { score, comment }` 메모리 상태로만 유지한다. 네트워크·Web Storage·URL에 기록하지 않으며 새 추천 조건으로 결과를 비울 때 함께 초기화한다.
- `REQ-5607`: 같은 추천 요청의 `다른 코스 보기`에서는 동일 장소의 선택을 유지하고, 추천 카드 상세 열기와 만족도 선택은 서로의 클릭 동작을 유발하지 않는다.
- `REQ-5608`: 추천 결과 제목, 지도 범례와 코스 변경 안내에서도 MMR·seed·확률 같은 내부 용어를 기본 노출하지 않는다.
- `REQ-5609`: 각 장소 만족도 아래에 `의견을 자유롭게 남겨주세요` textarea를 제공하고 최대 300자 제한, 현재 글자 수, 장소명을 포함한 접근 가능한 이름을 제공한다.
- `REQ-5610`: 점수 없이 의견만 작성하거나 의견 없이 점수만 선택할 수 있으며 한 입력이 다른 입력을 지우지 않는다.
- `REQ-5611`: 시작일·종료일 입력으로 일자별 일정이 생성되면 각 일정 장소에 추천 목록과 동일한 1~5 만족도와 최대 300자 자유 의견 UI를 제공한다.
- `REQ-5612`: 일정 장소의 장소 보기, 만족도 선택과 자유 의견 입력은 서로 독립적으로 동작하고 일차 hover·focus 지도 강조를 유지한다.
- `REQ-5613`: 같은 `placeId`가 추천 목록과 일정에 함께 있으면 어느 한쪽에서 바꾼 점수·의견을 다른 모든 표시 인스턴스에 즉시 반영한다.

## 입력과 출력

```text
PlaceRecommendationFeedback {
  placeId: string
  score: 1 | 2 | 3 | 4 | 5 | null
  comment: string(maxLength=300)
  scope: browser-memory-session
  persisted: false
}
```

- 입력: 사용자가 추천 카드에서 선택한 정수 만족도 1~5와 선택형 최대 300자 자유 의견.
- 출력: 같은 카드의 `aria-pressed`, 선택 강조, textarea 값, 글자 수와 완료 문구. 서버 출력은 없다.
- 추천 결과·장소 데이터 계약은 변경하지 않는다.

## 설계

```text
추천 결과
  -> 베타 카드: 장소 요약 + 추천 이유
       -> 상세보기: ID + 출처 + 점수 trace + 전체 라벨
       -> 만족도 1..5 + 자유 의견: 메모리 Map 갱신 + 카드 입력 상태 갱신
  -> 일자별 일정: 일차별 장소 보기 + 동일한 만족도 1..5 + 자유 의견
       -> 같은 placeId의 추천 카드·일정 장소 피드백 UI 동기화
  -> 새 조건으로 추천 무효화: 만족도 Map 초기화
  -> 같은 조건의 다른 코스: 기존 placeId 만족도 유지
```

- 카드 루트는 더 이상 하나의 중첩 불가능한 `button`이 아니라 `article`로 만들고 상세보기와 만족도 버튼을 각각 독립 제어로 둔다.
- 추천 이유는 기존 preference trace 중 utility가 높은 항목의 라벨만 사용하고 utility·weight 수치는 숨긴다.
- 장소 상세 패널은 기존 출처와 점수 trace를 유지하고 장소 ID를 내부 메타데이터에 추가한다.
- 피드백 UI는 공통 생성 함수로 구성하고 모든 표시 인스턴스에 `placeId`를 기록한다. 상태 변경 시 같은 `placeId`의 점수 버튼, 상태 문구, textarea와 글자 수를 함께 갱신한다.
- 기존 일정 장소 단일 버튼은 장소 행 컨테이너와 독립된 `장소 보기` 버튼으로 분리해 그 아래 피드백 버튼·textarea를 중첩 없이 배치한다.

## 예외와 폴백

- 웹 조사 설명이 없으면 `장소 설명을 준비하고 있어요.`를 카드에 표시하고 상세 패널은 현재 metadata-only 안내를 유지한다.
- 추천 이유 trace가 없으면 이유 칩 영역을 표시하지 않는다.
- 피드백을 다시 누르면 새 점수로 교체한다. 선택 취소는 이번 범위에서 제공하지 않는다.
- 300자를 넘는 입력은 HTML `maxLength`로 막고 현재 길이를 `n/300`으로 표시한다.
- 피드백 저장이 없다는 사실을 추천 목록 안내에 명시한다.

## 승인 기준

- `AC-5601`: 추천 카드에 ID, MMR, P/A/M, 연결 출처·확인일, seed 확률과 sim 수치가 보이지 않는다.
- `AC-5602`: 상세보기를 누르면 해당 장소의 ID, 출처·확인일, 내부 점수 trace와 전체 라벨을 확인할 수 있다.
- `AC-5603`: 장소별 1~5 만족도 중 하나를 선택·변경할 수 있고 상세보기가 함께 열리지 않는다.
- `AC-5604`: 새 추천 조건으로 기존 결과를 무효화하면 만족도 상태가 초기화되고 같은 조건의 코스 변경에서는 유지된다.
- `AC-5605`: 만족도 제어가 키보드로 접근 가능하고 각 점수 의미와 선택 상태를 보조기기에 전달한다.
- `AC-5606`: 1440px 데스크톱과 390px 좁은 화면에서 카드, 상세보기와 만족도 제어가 가로로 넘치지 않는다.
- `AC-5607`: Web Storage·네트워크 호출 없이 기존 추천·MBTI·지도·상세 동작과 정적 검증이 유지된다.
- `AC-5608`: 각 장소에서 최대 300자의 자유 의견을 작성·수정할 수 있고 글자 수가 갱신되며 점수 선택과 서로 독립적으로 유지된다.
- `AC-5609`: 시작일·종료일로 만들어진 모든 일자별 장소에 1~5 만족도와 최대 300자 자유 의견이 표시되고 장소 보기와 독립적으로 동작한다.
- `AC-5610`: 추천 목록과 일정에 같은 장소가 표시될 때 한쪽에서 변경한 점수·의견이 다른 쪽에 즉시 반영된다.
- `AC-5611`: 일정 피드백을 포함한 일차 카드가 데스크톱과 390px 화면에서 가로로 넘치지 않고 기존 일차 지도 강조가 유지된다.

## 구현 결과

- `map-ui/app.js`의 추천 카드 루트를 단일 `button`에서 `article`로 변경하고 장소 요약, 수치 없는 추천 이유, 독립된 상세보기와 1~5 만족도 버튼을 구성했다.
- 카드에서 ID, 관련도·MMR·P/A/M, 연결 출처·확인일, seed 확률과 similarity trace를 제거했다. 추천 결과 제목, 지도 범례와 코스 변경 안내의 MMR·seed·확률 용어도 여행자 문구로 교체했다.
- 장소 상세 패널에 ID를 추가하고 기존 웹 조사 원문 출처·확인일, 내부 추천 상세 점수와 41개 라벨을 유지했다.
- 장소별 만족도를 `state.recommendationFeedback` 메모리 Map으로 관리하고 `aria-pressed`, 점수별 접근 가능한 이름, 선택 완료 문구를 제공했다. 새 추천 조건으로 결과를 무효화할 때 Map을 비우며 같은 조건의 코스 변경에서는 유지한다.
- 같은 Map 값을 `{ score, comment }`로 확장하고 장소별 선택형 textarea, 최대 300자 제한, `n/300` 글자 수와 장소명을 포함한 접근 가능한 이름을 추가했다. 점수와 의견은 서로 독립적으로 입력·수정할 수 있다.
- `scripts/validate_ccu_mmr_dashboard.cjs`에 카드 내부 trace 미노출, 상세보기·만족도 DOM, 메모리 한정 상태와 초기화 경계를 검증하는 정적 회귀를 추가했다.
- 추천 목록과 일자별 일정이 `createRecommendationFeedback` 공통 UI를 사용하도록 구성했다. 일정 장소의 단일 버튼을 `schedule-place-card` 컨테이너와 독립된 장소 보기 버튼으로 분리해 만족도·의견 입력과 클릭이 겹치지 않는다.
- 같은 장소의 모든 피드백 UI에 `placeId`를 기록하고 `syncRecommendationFeedback`에서 점수 버튼, 상태 문구, textarea와 글자 수를 함께 갱신한다. 일정→추천 목록과 추천 목록→일정 양방향 동기화가 같은 메모리 Map을 사용한다.
- `scripts/validate_ccu_mmr_dashboard.cjs`에 공통 피드백 컴포넌트, 일정 카드 연결, 동일 장소 동기화 경계와 중첩 버튼 방지를 검증하는 회귀를 추가했다.
- 데스크톱에서 카드 10개, 4점 선택, 만족도 클릭 시 상세 미오픈, 상세보기의 ID·출처·MMR/P/A/M·6개 라벨 그룹을 확인했다. 390×844 iframe 실제 viewport에서는 카드 `clientWidth=319`, `scrollWidth=319`, 점수 영역 `clientWidth=295`, `scrollWidth=295`, 점수 버튼 폭 약 55px로 가로 넘침이 없었다.
