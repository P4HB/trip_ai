# 추천 평가 전략

- 문서 상태: 목표 설계 초안, 미구현
- 최종 수정일: 2026-08-09

현재 자동 추천 평가 파이프라인은 없다. 추천 기능을 구현하는 SPEC은 기능 코드와 함께 재현 가능한 평가 입력, 기준선, 회귀 결과를 정의해야 한다.

## 평가 계층

### 데이터 품질

- ID 중복·누락률
- 좌표 유효률과 지역 밖 좌표 수
- 카테고리, 이미지, 운영정보 등 주요 필드 커버리지
- 데이터 최신성 분포
- 원본과 정규화 결과의 추적 가능성

현재 수집기는 전체 건수, ID 무결성, 좌표 문제, 파일 해시를 `manifest.json`과 `quality_issues.csv`에 기록한다.

### 장소 프로필 라벨 파일럿 기준선 — 구현됨, 사람 검수 전

`SPEC-003`은 관광지·문화시설·축제·레포츠에서 100건을 층화 선정해 companion과 월별 적합도 AI 초안을 생성했다.

- 유형별 표본: 관광지 68, 문화시설 12, 축제 4, 레포츠 16
- 지역별 표본: 제주시 53, 서귀포시 47
- 장소와 대응되는 공식·공공 상세 웹 근거가 최종 프로필에 연결된 장소: 10건
- 나머지 90건: TourAPI 제목·신분류 기반 규칙 사전, 낮은 신뢰도와 사람 검수 필요 상태
- companion `null`: 157/500. 주로 시설 근거가 없는 `kids` 77건과 `parents` 80건을 보류함
- month `null`: 48/1,200. 개최기간을 월 적합도로 대체하지 않기 위해 축제 4건의 12개월을 보류함
- 평균 신뢰도(companion/month): 0.510/0.483
- 사람 검수 완료: 0건

이 결과는 라벨 생성 파이프라인과 척도 분포를 검토하기 위한 기준선이지 품질 통과를 뜻하지 않는다. 전체 데이터로 확대하기 전 최소한 다음 평가가 필요하다.

- 유형별로 표본을 다시 뽑아 두 명 이상이 독립 라벨링
- 5단계 순서형 값의 가중 일치도와 한 단계 이내 일치율 측정
- `kids`, `parents`의 시설 근거 커버리지 및 근거 없는 사전값 비율 측정
- 직접 출처가 있는 장소와 분류 사전만 사용한 장소의 일치도 차이 측정
- 월별 값의 장소 내 계절 변화와 유형별 획일화 정도 점검
- 불일치 사례를 기준 예시집에 반영한 뒤 같은 표본 재라벨링

### 필수 제약 정확성

- 필수 제약 위반률
- 제외 장소 재노출률
- 예산·시간·접근성 제약 처리 정확성
- 알 수 없는 데이터가 충족으로 잘못 처리된 비율

필수 제약 위반률의 목표는 원칙적으로 0이어야 한다. 제약 자체를 확인할 데이터가 없는 경우에는 성공으로 계산하지 않고 별도 집계한다.

### 랭킹 품질

- 오프라인 라벨이 있으면 Precision@K, Recall@K, NDCG@K
- 사용자 선택·저장·제외 같은 행동 지표
- 비개인화 기준선 대비 개선도
- 카테고리 및 지역별 품질 편차

행동 로그는 노출 편향을 포함하므로 단독 정답으로 사용하지 않는다.

### 다양성과 일정 가능성

- 상위 K개의 카테고리·지역 다양성
- 유사 장소 반복률
- 일정 시간 초과율
- 영업시간 충돌률
- 총 이동시간과 방문시간의 비율

### 설명 품질

- 설명의 점수 특징·필터 근거 일치율
- 출처 없는 변동 정보 포함률
- 불확실성 경고 누락률

### 운영 품질

- 요청 지연시간과 오류율
- 빈 결과율과 폴백 비율
- 알고리즘·데이터 버전 기록 누락률

## 골든 시나리오

추천 기능의 첫 SPEC은 최소한 다음 유형을 포함한 고정 시나리오 세트를 만들어야 한다.

- 취향 정보가 없는 첫 사용자
- 유아, 고령자 또는 접근성 요구가 있는 동행
- 엄격한 예산과 짧은 일정
- 렌터카 없이 이동하는 사용자
- 비 오는 날 또는 실내 선호
- 서로 충돌하는 필수 조건
- 후보 장소의 운영정보가 대부분 없는 경우
- 같은 카테고리만 높은 점수를 받는 경우
- 외부 이동시간 서비스가 실패한 경우

각 시나리오는 입력 스냅샷, 기대 불변조건, 허용 가능한 결과 범위를 포함해야 한다. 특정 장소 순위를 고정할 필요가 없다면 순위 대신 제약 준수와 결과 속성을 검증한다.

## 출시 게이트

정확한 임계값은 구현 SPEC에서 기준선과 함께 정한다. 최소 게이트는 다음과 같다.

- 필수 제약 회귀 없음
- 기존 기준선보다 핵심 랭킹 지표가 악화되지 않음
- 다양성과 일정 가능성 테스트 통과
- 설명이 실제 근거와 일치함
- 데이터·알고리즘 버전이 결과에 기록됨
- 실패와 빈 결과의 폴백이 검증됨
