# 추천 평가 전략

- 문서 상태: 목표 설계 초안, 미구현
- 최종 수정일: 2026-08-09

현재 자동 추천 평가 파이프라인은 없다. 추천 기능을 구현하는 SPEC은 기능 코드와 함께 재현 가능한 평가 입력, 기준선, 회귀 결과를 정의해야 한다.

## 평가 계층

### 데이터 품질

- ID 중복·누락률
- 좌표 유효률과 지역 밖 좌표 수
- 카테고리, 이미지, 운영정보 등 주요 필드 커버리지
- 데이터 최신성 분포
- 원본과 정규화 결과의 추적 가능성

현재 수집기는 전체 건수, ID 무결성, 좌표 문제, 파일 해시를 `manifest.json`과 `quality_issues.csv`에 기록한다.

### 필수 제약 정확성

- 필수 제약 위반률
- 제외 장소 재노출률
- 예산·시간·접근성 제약 처리 정확성
- 알 수 없는 데이터가 충족으로 잘못 처리된 비율

필수 제약 위반률의 목표는 원칙적으로 0이어야 한다. 제약 자체를 확인할 데이터가 없는 경우에는 성공으로 계산하지 않고 별도 집계한다.

### 랭킹 품질

- 오프라인 라벨이 있으면 Precision@K, Recall@K, NDCG@K
- 사용자 선택·저장·제외 같은 행동 지표
- 비개인화 기준선 대비 개선도
- 카테고리 및 지역별 품질 편차

행동 로그는 노출 편향을 포함하므로 단독 정답으로 사용하지 않는다.

### 다양성과 일정 가능성

- 상위 K개의 카테고리·지역 다양성
- 유사 장소 반복률
- 일정 시간 초과율
- 영업시간 충돌률
- 총 이동시간과 방문시간의 비율

### 설명 품질

- 설명의 점수 특징·필터 근거 일치율
- 출처 없는 변동 정보 포함률
- 불확실성 경고 누락률

### 운영 품질

- 요청 지연시간과 오류율
- 빈 결과율과 폴백 비율
- 알고리즘·데이터 버전 기록 누락률

## 골든 시나리오

추천 기능의 첫 SPEC은 최소한 다음 유형을 포함한 고정 시나리오 세트를 만들어야 한다.

- 취향 정보가 없는 첫 사용자
- 유아, 고령자 또는 접근성 요구가 있는 동행
- 엄격한 예산과 짧은 일정
- 렌터카 없이 이동하는 사용자
- 비 오는 날 또는 실내 선호
- 서로 충돌하는 필수 조건
- 후보 장소의 운영정보가 대부분 없는 경우
- 같은 카테고리만 높은 점수를 받는 경우
- 외부 이동시간 서비스가 실패한 경우

각 시나리오는 입력 스냅샷, 기대 불변조건, 허용 가능한 결과 범위를 포함해야 한다. 특정 장소 순위를 고정할 필요가 없다면 순위 대신 제약 준수와 결과 속성을 검증한다.

## 출시 게이트

정확한 임계값은 구현 SPEC에서 기준선과 함께 정한다. 최소 게이트는 다음과 같다.

- 필수 제약 회귀 없음
- 기존 기준선보다 핵심 랭킹 지표가 악화되지 않음
- 다양성과 일정 가능성 테스트 통과
- 설명이 실제 근거와 일치함
- 데이터·알고리즘 버전이 결과에 기록됨
- 실패와 빈 결과의 폴백이 검증됨
