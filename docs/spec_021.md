# SPEC-021: 원격 최신화와 로컬 SPEC 번호 재정비

- 상태: Implemented
- 작성일: 2026-08-21
- 최종 수정일: 2026-08-24
- 관련 이슈: 원격 `SPEC-019~020`과 로컬 미추적 `SPEC-019~054`의 번호 충돌 및 지도 UI 동시 변경
- 관련 문서: [문서 색인](README.md)
- 관련 코드: `docs/spec_*.md`, `docs/README.md`, `docs/data_contracts.md`
- 선행 SPEC: [SPEC-019](spec_019.md)

## 배경

2026-08-21에는 원격 `SPEC-016~018`과 충돌하던 로컬 재라벨링 문서를 재배치하고 원격 `9cb44cc`를 반영했다. 2026-08-22에는 원격 `94febe2`의 `SPEC-019`를 보존하기 위해 기존 로컬 문서를 `SPEC-020~054`로 옮겼다. 2026-08-24 원격 `b0046a2`가 새 `SPEC-020`과 5단계 베타 입력 UI를 추가했고, 로컬에는 같은 번호의 동기화 SPEC과 구현된 여행 MBTI UI가 남아 있다. 그대로 pull하면 문서 번호와 지도 UI 변경이 겹치므로 두 승인된 기능을 보존하는 통합이 필요하다.

## 목표

- 원격 `main`의 `b0046a2`를 fast-forward로 반영한다.
- 원격이 추적하는 `SPEC-001~020`을 해당 번호와 내용으로 유지한다.
- 기존 로컬 `SPEC-020~054`를 순서대로 `SPEC-021~055`로 옮겨 유실 없이 보존한다.
- 문서 ID, `REQ/AC` ID, 상호 링크, 색인과 다음 예약 번호를 실제 파일과 맞춘다.
- 원격의 5단계 베타 입력과 로컬의 여행 MBTI 개인화를 함께 제공하되 최종 확인 전에는 추천을 자동 실행하지 않는다.

## 비목표

- 로컬 라벨 데이터와 판정 결과 변경
- 로컬 변경 커밋·push 또는 미추적 파일 정리
- 5단계 입력이나 여행 MBTI 알고리즘 자체의 요구사항 변경

## 요구사항

- `REQ-2101`: pull 전에 원격과 겹치는 로컬 추적 변경을 복구 가능한 stash에 보관한다.
- `REQ-2102`: `main`을 `origin/main`으로 fast-forward하고 원격 커밋을 재작성하지 않는다.
- `REQ-2103`: 원격 `SPEC-020`을 보존하고 기존 로컬 `SPEC-020~054`를 `SPEC-021~055`로 일대일 재번호화한다.
- `REQ-2104`: 재번호화 대상의 제목 ID, `REQ/AC` ID, `SPEC-NNN`과 `spec_NNN.md` 참조에 같은 매핑을 적용한다.
- `REQ-2105`: 로컬 데이터·스크립트·수정 파일을 삭제하거나 덮어쓰지 않는다.
- `REQ-2106`: `SPEC-019` 여행 MBTI와 `SPEC-020` 단계형 입력을 통합하고, MBTI 적용은 취향 단계의 입력만 바꾸며 5단계 최종 실행 전 추천을 만들지 않는다.

## 입력과 출력

- 입력: 로컬 `main=94febe2`, `origin/main=b0046a2`, 로컬 추적 변경과 미추적 라벨링 산출물
- 출력: `HEAD=origin/main=b0046a2`, 원격 `SPEC-019~020`, 로컬 `SPEC-021~055`, 다음 예약 번호 `SPEC-056`, 단계형 입력과 여행 MBTI가 함께 동작하는 지도 UI

## 설계

1. 원격 변경 경로와 실제 로컬 내용 변경의 교집합을 확인한다.
2. 로컬 `SPEC-020~054`를 높은 번호부터 `SPEC-021~055`로 이동하고 내부 참조를 같은 매핑으로 갱신한다.
3. 겹치는 추적 문서만 stash한 뒤 `git pull --ff-only origin main`을 실행한다.
4. stash를 적용해 원격·로컬 색인을 병합하고 로컬 변경을 작업 중 상태로 복원한다.
5. 브랜치 SHA, SPEC 파일·제목·링크·색인, 충돌 부재를 검증한다.
6. 원격 단계형 입력을 기준 화면으로 두고 취향 단계에 여행 MBTI 진입·적용·해제를 결합한다.
7. 구문, 선호 엔진, CCU-MMR, 대시보드 계약과 로컬 HTTP 데모를 검증한다.

## 예외와 폴백

- fast-forward가 불가능하면 merge commit을 만들지 않고 중단한다.
- 원격과 로컬의 같은 번호 문서는 어느 쪽도 덮어쓰지 않고 로컬 문서를 다음 번호로 이동한다.
- 두 SPEC의 승인된 동작이 충돌하면 최종 추천 실행 시점은 `SPEC-020`, 개인화 프로필 계약은 `SPEC-019`를 따른다.

## 승인 기준

- `AC-2102`: 원격 `SPEC-019~020`과 로컬 `SPEC-021~055`가 존재하고 제목 ID가 파일명과 일치한다.
- `AC-2103`: 문서 색인의 SPEC 항목과 실제 파일이 일치하고 다음 예약 번호가 `SPEC-056`이다.

- `AC-2105`: 로컬 수정·미추적 작업이 보존되고 충돌 파일이 없다.
- `AC-2106`: 5단계 DOM·검증·최종 실행 지연과 18문항·8개 여행 MBTI·개인화 요청 회귀가 함께 통과한다.

## 구현 결과

- 원격 `main`을 `b0046a2`로 fast-forward했으며 `HEAD`와 `origin/main`이 일치한다.
- 원격 `SPEC-020`을 그대로 보존하고 기존 로컬 `SPEC-020~054`를 `SPEC-021~055`로 재번호화했다. 제목 ID, `REQ/AC` ID, 범위 표기, 상호 참조와 색인을 같은 매핑으로 갱신했다.
- 문서 색인의 다음 예약 번호를 `SPEC-056`으로 갱신했으며 로컬 수정 파일과 미추적 라벨링 산출물을 삭제하거나 덮어쓰지 않았다.
- 원격의 5단계 입력 화면을 기준으로 취향 단계와 상단에 여행 MBTI 진입점을 유지했다. 18문항·최대 3개 가상 장소 선택 결과는 프리셋 대신 연속 가중치로 적용되고 5단계 확인 요약에 유형을 표시한다.
- MBTI 적용·해제는 추천을 자동 실행하지 않는다. 사용자가 5단계 최종 실행 버튼을 누른 뒤에만 `ccu-mmr-request-v4-personalized` 요청과 추천 결과를 만든다.
- `node --check map-ui/preference-elicitation.js`, `node --check map-ui/ccu-mmr.js`, `node --check map-ui/app.js`, `node scripts/test_preference_elicitation.cjs`, `node scripts/test_ccu_mmr.cjs`, `node scripts/validate_ccu_mmr_dashboard.cjs`가 통과했다.
- 로컬 HTTP 브라우저에서 `동행자 → 날짜 미정 → 여행 방식 → 여행 취향 → 조건 확인`을 진행하고 18문항·3개 pair로 `AOL · 바람길 탐험가`를 적용했다. 적용 직후 추천 0건, 최종 실행 후 개인화 요청과 추천 10건을 확인했다.

## 설계와 달라진 점

브라우저가 이전 정적 JavaScript와 새 HTML을 섞어 재사용하지 않도록 2026-08-24 통합 버전의 1차 자산 URL에 cache-busting query를 추가했다. 파일 내용과 런타임 계약은 바꾸지 않는다.

## 알려진 제한

로컬 변경은 이번 동기화에서 커밋하거나 원격에 공유하지 않는다.

이번 재번호화 범위 밖의 기존 `SPEC-012`에는 저장소에 존재하지 않는 `spec_011.md` 링크가 남아 있다. 이번 원격 동기화나 번호 이동으로 생긴 문제는 아니다.
