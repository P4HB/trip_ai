## 배경

지도 탐색 필터가 추천 후보를 줄이고 결과를 지운다. 코스 재선택마다 평가 세션을 교체하여 대기 중 의견이 유실될 수 있다. 식당 판정의 근거 검증 실패 후에도 설명이 남고, 식당 선택 후 이동 표시가 기존 경로를 유지한다. 동시 LLM 요청의 모델 출처가 공유 상태에 의존한다. Windows에서 SQLite 연결 해제와 CRLF 번들 파싱 때문에 검증이 실패한다. 기존 미커밋 Gemini 개선 작업과 빈 임시 파일도 있다.

## 목표와 비목표

사용자가 요청한 리뷰 수정과 파일 정리를 승인된 범위로 수행한다. 기존 미커밋 개선은 보존하고 회귀를 검증한다. 실제 외부 API 호출·운영 배포·데이터 재수집·추천 알고리즘의 점수 변경은 비목표다. 비밀 파일과 실제 사용자 피드백은 읽거나 변경하지 않는다. 다른 작업의 worktree와 별도 Git 저장소는 일괄 삭제하지 않는다.

## 요구사항

- REQ-001: 지도 검색·유형 필터와 추천 후보/평가 상태를 분리한다.
- REQ-002: 코스 재선택·anchor 변경은 평가 세션과 누적 평가를 유지한다. 실제 조건 변경 시 이전 스냅샷 저장을 완료하거나 독립 재시도로 보존한다. 렌더 함수는 세션을 만들지 않는다.
- REQ-003: 평가 UI를 공통 등록·동기화 경계로 모으고, 결과 초기화 시 경고·검증 후보·JSON·수치도 함께 초기화한다. 화면 로직과 공통 상수를 책임별 모듈로 분리한다.
- REQ-004: 근거 없는 식당 설명·기준 판정은 unknown/안전한 설명으로 바꾼다. 식당 선택은 해당 삽입 이동 구간을 표시하고 이전 직접 구간을 중복 표시하지 않는다.
- REQ-005: 모델명·사용량은 요청별 결과에 귀속시킨다. SQLite 연결을 명시적으로 닫고, 서버 유휴 시에도 90일 보존 정책을 실행한다. 속도 제한 키를 정리하며 전달 IP는 명시적으로 신뢰한 프록시에만 허용한다.
- REQ-006: 생성기에서 CRLF/LF를 모두 읽고, 활성 데이터 위치를 manifest로 관리한다. 브라우저 번들은 실행에 필요한 필드만 전달하며 오프라인 근거 원본은 보존한다.
- REQ-007: 프로토타입 생성기의 문자열 패치가 존재하면 설정 기반으로 대체하거나 모든 패치 실패를 검출한다. 사용하지 않는 배포본을 검사하는 회귀 테스트를 현재 실행 경계에 맞춘다.
- REQ-008: CSS와 개발 진단 표시를 정리한다. 이력 문서·정본 데이터·기존 작업을 보존하면서 빈 임시 파일과 중복 산출물을 정리하고 문서 색인을 갱신한다. 검증한 변경을 명시적 파일 목록으로 커밋한다.

## 입력과 출력 / 설계

지도·추천의 장소 ID와 좌표 순서(lng, lat)는 유지한다. 추천 결과와 평가 session_id/revision 계약은 유지하며 재선택 시 이전 장소 평가를 같은 세션에 합친다. 이름 없는 평가의 서버 전송 제한은 유지한다. 이전 세션의 저장 큐는 화면 상태와 분리한다. DOM에서 제거된 평가 위젯은 등록 목록에서 해제한다.

LLM 구조화 응답에 대한 요청별 모델·사용량 래퍼를 추가하고 기존 generate_structured 호출 호환성을 유지한다. 만료 정리는 서버 service_actions 주기에 연결한다. v2 평가 경로는 기존 자료·클라이언트의 보존 기간 종료가 확인되지 않았으므로 분리 보존한다. 새 요구사항이 기존 SPEC-060의 재추천 세션 재생성 규칙보다 우선한다.

누적 평가가 현재 코스의 100개 제한을 넘을 수 있으므로 v3 세션은 최대 3,000개 장소를 허용한다. 현재 지도 전체 2,153개를 포괄하는 유한 상한이며 본문 2MiB·의견 300자·v2 100개 상한은 유지한다. UI 완료 수는 현재 코스 기준이고, 전송 스냅샷의 완료 수는 현재 코스와 이전에 평가한 장소의 합집합 기준이다.

## 예외와 폴백

평가 저장 실패는 동일 스냅샷으로 재시도한다. 이름이 없으면 전송하지 않는다. 식당 이동 증거가 없으면 이전 경로를 확정된 선택 경로로 표현하지 않는다. 외부 서비스 품질은 모의 응답 검증과 구분한다. 과거 리뷰에 나온 파일이 현재 없으면 삭제/수정을 꾸며내지 않고 결과에 기록한다.

## 구현 결과

- `map-ui/app.js`: 3,217줄의 결합 코드를 상태·평가·일정 화면·입력 단계·취향 화면·지도·장소 상세 모듈로 분리했다. `domain.js`로 원자 feature·표시명·지역·목적별 유형을 공유한다. `styles/`의 기능별 CSS는 기존 적용 순서를 보존한다. 개발용 JSON·수치는 `?debug=1`에서 표시한다.
- 탐색 필터는 추천·평가를 지우지 않고 추천 후보도 제한하지 않는다. 동일 여행 조건의 재추천·중심 변경은 세션과 과거 평가를 유지한다. 의견은 예약 시 스냅샷을 만들어 실제 조건 변경 후에도 기존 세션으로 저장·재시도한다. 평가 DOM은 등록 목록으로 동기화하고 제거된 노드는 해제한다. 초기화 시 경고·검증 후보·입출력 JSON·수치도 비운다.
- 식당 리뷰 근거가 잘못됐거나 없으면 판정 기준을 unknown으로 바꾸고 안전한 이유로 교체한다. 식당 선택 이동은 기존 직접 구간을 대체하며 동일 구간의 복수 식사 삽입은 확인 필요로 표시한다. 원본 시간표와 이후 관광 일정은 변경하지 않는다.
- `StructuredResponse`는 dict 호환 값과 요청별 모델·사용량을 보관한다. 일정·식당·방문 추론은 공유 클라이언트의 마지막 값에서 출처를 읽지 않는다. 오류 응답과 SQLite 연결을 닫는다.
- 피드백 공통 계약·v3 검증·v2 호환은 각각 별도 모듈이다. 서버 유휴 상태에서도 60초 간격으로 만료 자료를 삭제한다. 속도 제한의 만료 키를 제거하고 최대 10,000개로 제한한다. 전달 IP는 명시적으로 신뢰한 프록시에서만 받는다. 인스타 작업 수명주기는 `job_store.py`로 분리했다.
- `config/active_datasets.json`과 `scripts/lib/data_io.mjs`를 도입했다. 브라우저 번들은 19,034,316→6,345,572바이트(약 66.7% 감소), 전체 라벨 근거 압축 파일은 1,940,110바이트다. 장소 2,153·추천 가능 1,663·각 41축을 보존했다. 인스타 Catalog의 실제 1,663개 근거 연결도 확인했다. 일정 카탈로그의 의미상 버전은 유지되고 sourceHash만 변경됐다. 생성물 3개는 재실행 후 바이트 단위로 동일했다.
- `.gitattributes`와 파싱 개선으로 LF/CRLF 간 생성 결과를 일치시켰다. 쓰이지 않는 별도 사이트의 과거 취향 엔진 복사본 비교를 제거하고 실제 지도 진입점을 검사한다.
- 기존 Gemini 오류 분류·기본값·폴백·로컬 실행기 변경을 보존했다. 빈 `python`, 일회성 `_inspect.py`를 제거하고 테스트 산출물은 제외되는 `tmp/`에 둔다. 과거 연구·인계·구현 요청은 `docs/research/`, `docs/archive/`로 옮겼고 누락된 SPEC 색인 34개를 복구했다. 정본 데이터, 검수 이력, 테스트 증거, 별도 저장소는 보존했다.

## 설계와 달라진 점

- 첨부 리뷰가 언급한 `scripts/stage1/build_prototype.py`, `web/`, `tmp/osm-tile-fix/`, 빈 `tests/`는 현재 작업 사본에 없다. 존재하지 않는 생성기를 새로 만들거나 별도 작업의 worktree를 삭제하지 않았다.
- 최초 save_session의 경쟁 상태는 기존 `_prune` DELETE가 쓰기 트랜잭션 잠금을 먼저 획득하므로 재현되지 않았다. 동일 최초 요청 2개의 동시 저장 회귀 검증을 추가하고 연결 종료를 수정했다.
- 24축/17축 전체 근거는 삭제하지 않고 오프라인 sidecar에 보존했다. 과거 버전 데이터 생성기는 역사적 입력 재현을 위해 유지하며 활성 지도 입력만 manifest로 고정했다.
- v2 호환은 즉시 삭제 대신 격리했다. 피드백과 인스타 HTTP 서버는 서로 다른 접근 정책을 유지하며 무리하게 통합하지 않았다.

## 알려진 제한

실제 외부 LLM 품질·운영 배포는 SPEC-083/107/108의 별도 검증을 유지한다.

- 메모리의 평가 재시도는 페이지 종료·새로고침 후에는 복구되지 않는다. 영속 개인정보 저장을 추가하지 않았다.
- 식당 선택은 검증된 삽입 구간을 표시하며 이후 관광 일정 전체를 다시 생성하지 않는다.
- 신뢰할 프록시 IP는 배포 환경에서 지정해야 한다. 기본값은 전달 헤더를 무시하고 연결 주소별 제한을 적용한다.
- 사용자 결정: `.env.example`은 수정·커밋에서 제외하고 기존 미커밋 변경을 그대로 보존한다. 이 파일의 추가 열람·수정·스테이징은 하지 않았다. 실제 `.env`는 열람·편집·커밋하지 않았다.
