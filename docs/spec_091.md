## 배경

v1.3은 MVP 실험의 상세 일정과 출시 절차를 본문에서 과도하게 강조하고 숙박업소 실증을 구체적인 진입 경로처럼 반복했다. 사용자는 해당 가정의 의미와 현재 단계에서 검증 계획이 필요한지 지적하고, 문제·솔루션·시장·고객·실행방안·기대효과의 여섯 평가 기준을 다시 제시했다. 강의의 핵심을 사업·앱 기획에 반영하되 실증 수행이나 결과를 필수로 추가하지 않는 방향으로 문서를 정리한다.

## 목표

- Spec의 주요 사업 내용을 평가 6항목과 같은 순서로 구성한다.
- L01~L03의 핵심, 앱의 필수 범위·Actor·요구사항·프로세스 연결을 유지한다.
- 본문의 MVP 내용은 현재 범위와 향후 확인 방향으로 축약한다.
- 숙박업소를 확정 초기 고객처럼 취급하는 문맥을 제거하고 고객 도입 프로세스를 일반화한다.

## 비목표

- 제품 기능·배포·데이터 변경, 실제 인터뷰·실증·영업·계약·지출.
- 다른 산출물 추가 요구, 시장 규모·고객·가격·성과 근거 창작.
- 제주의 MVP 제한을 사업 전체의 지역 제한으로 확대하기.

## 요구사항

- REQ-001: 본문 1~6장을 문제·원인, 솔루션, 타겟시장, 타겟고객, 사업 실행방안·수익모델, 기대효과 순서로 정리한다. 평가표 대조도 동일 위치로 갱신한다.
- REQ-002: 사업 개요와 5W1H, 원인 분석, 고객별 가치·상품·과금·채널, 초기 진입·자원·원가와 성장 순서를 유지한다. 사실·설계·가정·미결정을 구분한다.
- REQ-003: 현재 제주 MVP 범위·구현 상태와 짧은 향후 확인 방향만 본문에 남긴다. D0/10영업일 실행표·TN 상세 시험·출시 승인 절차는 선택 보완 문서로 옮기고 후속 운영 초안으로 명시한다.
- REQ-004: 숙박은 목표 고객군 중 하나로 유지한다. 숙박 실증·QR 실험·임의 단가를 사업의 고정 전제로 삼지 않는다. L2-B는 고객 도입·데이터 운영·갱신 흐름으로 일반화한다.
- REQ-005: App 기획 부분에서 Actor, 핵심·부가 기능, 기능/비기능 요구사항과 추적, 화면·정보 흐름·기술 환경을 간결하게 유지한다. 기존 REQ/AC/NFR/BP ID는 보존하고 문서 간 참조를 동기화한다.
- REQ-006: 기존 3쪽 draw.io/PDF와 제출 안내·평가 대조·보완 문서를 v1.4로 맞추고 시각·구조 검증한다. 원본 자료와 Git 제외를 유지한다.
- REQ-007: 제출 Spec 본문을 심사자가 읽는 사업·앱 기획 문체로 정리한다. 이전 대화에 대한 해명, 집계 방법·표본 한계의 장황한 설명, 작성 범위·평가 대응 메모를 제거한다. 문제·원인·타깃·상품·수익·실행방안·기대효과는 구체적으로 유지하고, 사업 계획은 계획형 문장으로 표현한다. 베타 의견은 기획에 필요한 관찰 주제로만 요약한다.

## 입력과 출력

- 입력: 사용자 재제시 요구사항·평가표 6문항, v1.3 산출물, 앞서 확인한 강의와 공식 비교 자료.
- 출력: 제출 Spec v1.4, 도면 3쪽과 같은 정의의 PDF, 동반 Markdown. v1.3은 `_work/`에 보존한다.
- 현재 기준일은 2026-09-30이다. 제출 문체 편집 시 공식 서비스 소개 3곳을 다시 확인해 해당 비교의 확인일을 2026-09-30으로 갱신했다.

## 설계

사업 개요 뒤 평가 항목 6장, 앱 기획 1장, 강의 반영·출처 1장의 8장 구조로 바꾼다. 상세 실행 초안은 보완 문서의 후속 검토 부록에 둔다. L1은 공통 가치 교환을 유지하고 L2-B의 특정 숙박 채널 및 과도한 출시 통제 표기를 고객 도입·데이터 품질 확인으로 정리한다. 현장 인터뷰·실증 결과가 없다는 사실과 유사 서비스 조사를 구분한다.

2026-09-30 추가 요청에 따른 편집은 산출물 #1 Markdown의 제출 적합성에 집중한다. 사업 전체와 제주 MVP의 관계는 도입·확장 전략 안에서 설명한다. 표본 수·집계 한계와 작성 경위는 내부 기록에 보존하고 제출 본문에서는 제외한다. 기능의 현재 상태와 목표 설계는 §7에 모으고, 본문 각 절에서 같은 단서를 반복하지 않는다. 기존 장 번호와 REQ/AC/NFR/BP/화면 ID를 유지한다. 사업 방향·상품·도면 흐름은 바꾸지 않으며 PDF 재생성은 이번 문장 편집 범위에 포함하지 않는다.

## 설계와 달라진 점

전체 8장과 기존 요구사항·도면 참조는 유지하고 각 장 안의 소제목과 표를 제출 문체에 맞게 정리했다. 추가 요청은 Markdown 편집으로 한정해 PDF를 재생성하지 않았다. 사업성·MVP 효과의 실제 검증을 문서 작성의 완료 조건으로 추가하지 않았다.

## 알려진 제한

현재 기획의 사업성·실제 고객 반응·지불 의사는 미검증이다. 세부 운영 초안 보존은 그 절차의 승인·실행을 의미하지 않는다.
