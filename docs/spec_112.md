- 상태: Implemented

- 관련 요청: 문서·임시 파일, 특히 draw.io로 만든 자료를 삭제한다.
- 관련 문서: [문서 색인](README.md), [SPEC-111](spec_111.md), [SPEC-087](spec_087.md)
- 관련 코드: `.gitignore`, `scripts/evaluate_preference_weight_budget.cjs`, `scripts/build_feedback_report.mjs`, `scripts/evaluate_restaurant_candidates.py`의 실행 예시

## 배경·목표·비목표

SPEC-111에서 보관 폴더로 옮겼던 문서와 Git 제외 영역의 생성 제출본·도면·백업이 남아 있다. 사용자의 후속 요청에 따라 보관 대신 삭제한다. 실행 코드·정본 데이터·현재 기준 문서·SPEC 이력·강의 원본·별도 저장소·비밀 파일은 삭제 범위가 아니다. `.env.example`은 사용자가 지정한 수정·커밋 제외를 유지한다.

## 요구사항과 설계

- REQ-001: `kaist_app/제출용/`의 생성 문서·draw.io·PDF 6개와 `kaist_app/_work/`의 작업 자료 106개를 제거한다. Git 미추적 자료이므로 Windows 휴지통을 사용하며 저장소 안에 새 백업을 만들지 않는다.
- REQ-002: `docs/archive/`, `docs/research/`의 일회성 기록, `docs/business_model_and_social_impact.md`, `artifacts/`, `reports/`, `.obsidian/workspace.json`과 빈 `tmp/`를 정리한다. 추적 파일은 기존 Git 이력으로 복구할 수 있다.
- REQ-003: 현재 문서의 삭제 파일 링크를 정리하고 과거 SPEC에는 당시 기록임을 표시한다. 평가 JSON·피드백 HTML의 기본 출력과 식당 평가 실행 예시는 `tmp/`를 사용하고 기존 산출물·편집기 작업 상태·draw.io 자동 백업이 다시 추적되지 않게 한다.
- REQ-004: 삭제 전 절대 경로가 현재 저장소 내부인지 확인하고 비밀 파일명·키 파일·하위 저장소·재분석 지점이 포함된 대상은 중단한다. 내용을 읽지 않는 파일 목록 검사로 범위를 검증한다.

## 입력·출력·예외·영향 범위

입력은 명시한 로컬 경로와 사용자 삭제 요청이다. 출력은 파일이 제거된 작업 사본, 갱신된 색인·링크·ignore 규칙과 커밋이다. 런타임·데이터 스키마 변경은 없다. 휴지통 이동 실패 시 영구 삭제로 자동 전환하지 않는다. 원래 생성 작업의 보존 결정은 이번 사용자 요청으로 해당 산출물에 한해 대체된다.

## 구현 결과

- REQ-001 / AC-001: 생성 제출 자료 6개(207,759바이트)와 `_work` 작업 자료 106개(12,514,507바이트)를 Windows 휴지통으로 옮겼다. `kaist_app/`에는 강의 원본만 남겼다.
- REQ-002 / AC-001: Git 추적 중이던 일회성 문서·보고서·스크린샷·작업 상태 17개(12,161,914바이트)와 빈 `tmp/`를 삭제했다. 삭제한 추적 자료는 `origin/main` 커밋 `8fbab8e`에서 복구할 수 있다(원래 기록한 로컬 커밋 `7ec3914`는 재적용 과정에서 대체됨). 합계 129개, 24,884,180바이트를 작업 사본에서 제거했다.
- REQ-003 / AC-002: 색인의 삭제 자료 항목과 연결된 링크를 정리했다. 제출·검증 관련 과거 SPEC에는 후속 삭제 기록을 연결하고 당시 결과를 유지했다. 수정 Markdown 21개의 로컬 링크 239개를 검사하여 누락이 없었다.
- REQ-003 / AC-003: 평가 JSON 기본 출력은 `tmp/evaluation/`, 피드백 HTML은 `tmp/reports/`로 옮겼다. 식당 평가 실행 예시도 `tmp/evaluation/`을 사용한다. `artifacts/`, `reports/`, Obsidian 작업 상태와 draw.io 자동 백업을 Git에서 제외했다.
- REQ-004: 절대 경로·재분석 지점·보호 파일명 검사를 거쳤다. 영구 삭제한 파일은 17개 모두 Git 추적 여부를 확인했으며 비밀 파일은 읽거나 변경하지 않았다. 정리 대상 9개 경로의 부재와 기준 문서·강의·데이터·별도 저장소 등 보존 대상 15개 경로의 존재를 확인했다.

### 검증

- `node --check scripts/evaluate_preference_weight_budget.cjs`: 통과.
- `node --check scripts/build_feedback_report.mjs`: 통과.
- `scripts/evaluate_restaurant_candidates.py`의 Python AST 문법 검사: 통과.
- 수정 Markdown의 상대 링크 존재 검사: 239개 통과.
- `git check-ignore --no-index`로 임시 결과·보고서·편집기 상태·도면 자동 백업 7개 경로가 제외되고 `.obsidian/app.json`은 계속 추적 가능한 것을 확인했다.
- 수정 경로를 명시한 `git diff --check`: 통과. Windows 줄바꿈 변환 안내만 있었고 오류는 없었다.
- 커밋은 수정·삭제 경로를 명시적으로 지정하며 사용자 요청에 따라 `.env.example`을 제외한다. 실제 피드백 데이터 읽기나 보고서 재생성, 외부 API 호출은 필요하지 않아 실행하지 않았다.

## 설계 차이·제한

데이터 검증 manifest가 해시를 참조하는 `data/` 내부 보고서는 검증 입력의 일부이므로 보존한다. 강의 원본 안의 예제 draw.io는 이번에 생성한 도면이 아니므로 유지한다. 재사용 가능한 제품 기능 테스트는 삭제하지 않는다.
