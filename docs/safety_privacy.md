# 안전 및 개인정보 원칙

- 문서 상태: 적용 원칙
- 최종 수정일: 2026-08-09

## 비밀과 외부 서비스

- API 키는 환경 변수 또는 Git에서 제외된 로컬 환경 파일에서만 읽는다.
- 키, 인증 헤더, 키가 포함된 요청 URL을 로그·오류·문서·생성 데이터에 기록하지 않는다.
- 브라우저 번들에 서버용 비밀을 포함하지 않는다.
- 외부 데이터의 이용약관, 표시 의무, 캐시·재배포 조건을 배포 전 확인한다.

## 사용자 데이터 최소화

- 추천에 필요하지 않은 실명, 연락처, 정확한 위치 이력은 수집하지 않는다.
- 위치는 가능한 경우 행정구역, 격자, 근처 장소 ID처럼 낮은 정밀도로 처리한다.
- 정확한 위치가 필요하면 목적, 보관 기간, 삭제 방법을 명시하고 동의를 받는다.
- 사용자 프로필과 행동 로그에는 보관 기간과 삭제 정책이 필요하다.
- 민감한 취향이나 접근성 정보는 목적 외로 사용하지 않는다.

## 여행 정보 안전성

- 영업시간, 휴무일, 가격, 교통, 날씨, 위험 정보는 변동될 수 있음을 데이터 모델에 반영한다.
- 출처와 확인 시각이 없는 변동 정보를 확정적으로 안내하지 않는다.
- 운영정보가 없거나 오래되었으면 사용자에게 직접 확인하도록 표시한다.
- 의료, 재난, 출입 제한 등 안전에 중요한 정보는 추천 점수만으로 판단하지 않고 권위 있는 최신 출처 확인 경로를 제공한다.

## 추천 공정성과 제어

- 광고, 제휴, 인기도, 편집 추천이 순위에 영향을 주면 구분할 수 있어야 한다.
- 특정 지역·가격대·사업자만 반복 노출되는지 평가한다.
- 사용자는 추천 조건을 확인하고 수정하며 장소를 제외할 수 있어야 한다.
- 접근성 요구를 단순 선호 점수로 낮추지 않고 필요한 경우 필수 제약으로 처리한다.

## 설명의 신뢰성

- 추천 이유는 실제 사용한 특징과 데이터에서만 생성한다.
- 장소에 대한 근거 없는 장점, 운영 상태, 가격, 이동시간을 생성하지 않는다.
- 추정과 확인된 사실을 구분하고 불확실성을 숨기지 않는다.
- 사용자에게 내부 추론을 노출하는 대신 검증 가능한 조건, 출처, 점수 요인을 간결하게 제공한다.

## 변경 시 확인 사항

사용자 프로필, 위치, 행동 로그, 외부 AI 모델 또는 제휴 랭킹을 도입하는 SPEC에는 다음을 포함한다.

- 수집 필드와 목적
- 저장 위치, 접근 주체, 보관 기간, 삭제 방법
- 외부 전송 대상과 최소화 방법
- 사용자 고지와 제어 방식
- 오용·유출·잘못된 추천에 대한 폴백과 테스트
