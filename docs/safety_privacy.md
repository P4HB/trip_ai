# 안전 및 개인정보 원칙

- 문서 상태: 적용 원칙
- 최종 수정일: 2026-09-02

## 비밀과 외부 서비스

- API 키는 환경 변수 또는 Git에서 제외된 로컬 환경 파일에서만 읽는다.
- 키, 인증 헤더, 키가 포함된 요청 URL을 로그·오류·문서·생성 데이터에 기록하지 않는다.
- 브라우저 번들에 서버용 비밀을 포함하지 않는다.
- 외부 데이터의 이용약관, 표시 의무, 캐시·재배포 조건을 배포 전 확인한다.
- 자연어 mapper나 설명 표현을 외부 AI 모델에 맡기면 구조화에 필요한 최소 구간만 전송하고 장소·사용자 전체 프로필을 기본 전송하지 않는다.

## 사용자 데이터 최소화

- 추천에 필요하지 않은 실명, 연락처, 정확한 위치 이력은 기본 수집하지 않는다. 베타 평가 로그 구분을 위해 사용자가 명시적으로 입력한 이름 또는 별칭만 아래 v3 정책에 따라 제한적으로 수집한다.
- 위치는 가능한 경우 행정구역, 격자, 근처 장소 ID처럼 낮은 정밀도로 처리한다.
- 정확한 위치가 필요하면 목적, 보관 기간, 삭제 방법을 명시하고 동의를 받는다.
- 사용자 프로필과 행동 로그에는 보관 기간과 삭제 정책이 필요하다.
- 민감한 취향이나 접근성 정보는 목적 외로 사용하지 않으며 외부 모델 입력과 분석 로그에서 기본 제외한다.
- 자연어 원문을 저장해야 하면 mapper trace에 필요한 최소 구간, 보관 기간과 삭제 경로를 별도 SPEC에서 정한다.

### 여행 MBTI 개인화 v1

- 질문·가상 장소 선택·18개 feature estimate와 여행 MBTI 결과는 현재 탭의 JavaScript 메모리에만 두고 Web Storage, URL, 서버, 분석 이벤트에 기록하지 않는다.
- 새로고침이나 탭 종료 시 프로필이 사라지며 계정·기기·정확한 위치와 결합하지 않는다.
- 공유 문구에는 3글자 유형 코드, 유형 이름, 공개 설명만 포함한다. 원문 답변, feature weight·confidence, 여행 날짜·동행·위치는 포함하지 않는다.
- 가상 장소 카드는 실제 장소명·실제 또는 생성 사진을 사용하지 않고 가상임을 명시한다.
- 여행 MBTI는 심리 진단이나 접근성·안전 판정이 아니며 높은 개인화 confidence도 장소 라벨 품질과 방문 가능성을 보장하지 않는다.

### 추천 만족도 서버 자동 적재 v3

- 이름 또는 별칭이 입력된 상태에서 여행 조건·MBTI 질문과 가상 장소 선택·프로필·추천/일정 결과·장소별 현재 만족도와 자유 의견은 사용자가 만족도 또는 의견을 처음 변경할 때부터 동일 출처 서버로 자동 전송한다. 페이지 방문·추천 결과 표시·이름 입력만으로는 전송하지 않는다.
- 평가 영역에 이름 또는 별칭, 전송 시점·필드, 서비스 개선 목적과 90일 보관을 고지하고 실명 대신 별칭 사용과 연락처 비입력을 안내한다. 사용자가 입력한 이름 또는 별칭 외에 계정, 연락처, 정확한 현재 위치, IP, User-Agent와 쿠키는 저장하지 않는다.
- 서버는 Rail Desk와 분리된 전용 SQLite에 추천 세션 UUID별 최신 revision·시각·스키마 버전·payload 한 행만 저장한다. 기존 v2 제출 테이블은 호환성을 위해 분리 유지한다.
- 공개 조회 API는 제공하지 않는다. 삭제 요청은 운영자가 세션 ID를 기준으로 처리하며, 만료 레코드는 서비스 시작과 새 적재 시 삭제한다.
- 전송 실패 시 브라우저 메모리 입력을 유지하고 동일 revision·payload로 자동 재시도한다. Web Storage와 `sendBeacon`은 사용하지 않는다.

### Kakao 공개 후기 스냅샷 v1

- 공개 후기 작성자 표시명은 원본 수집 파일 밖의 파생 DB·API·Map UI에 포함하지 않는다.
- 리뷰 카탈로그는 승인된 장소 교차 관계, 후기 본문·별점·작성일·태그·좋아요와 Kakao 원문 링크만 제공하고 추천 만족도 DB와 분리한다.
- 화면에는 수집 시점과 최대 5건 스냅샷이라는 제한을 고지하며 현재 정보 확인을 위한 Kakao 원문 링크를 제공한다.
- 리뷰 내용은 추천 점수·라벨·사용자 프로필과 결합하지 않는다. 외부 데이터의 이용약관·저작권·재배포 조건은 운영 공개 범위를 넓히기 전에 다시 확인한다.

## AI 초안과 여행 정보 안전성

- 현재 전체 장소 프로필은 사람 검수 전 `ai_draft`다. 내부 실험 외 실행을 막고, 결과·trace·평가 자료에 이 상태를 표시한다.
- AI 초안 confidence는 장소 품질·안전·영업 가능성의 보장이 아니다.
- 영업시간, 휴무일, 가격, 교통, 날씨, 행사일과 위험 정보는 변동될 수 있음을 데이터 모델에 반영한다.
- 출처와 확인 시각이 없는 변동 정보를 확정적으로 안내하지 않는다.
- 운영정보가 없거나 오래됐으면 `unknown` 또는 `verification_required`로 유지하며 `pass`로 간주하지 않는다.
- 의료, 재난, 출입 제한 등 안전에 중요한 정보는 추천 점수로 판단하지 않고 권위 있는 최신 출처 확인 경로를 제공한다.

## 제약과 추천 제어

- 필수 제약을 선호 점수로 낮추거나 높은 적합도로 상쇄하지 않는다.
- 접근성 요구는 companion의 `parents`·`kids` 값으로 대체하지 않는다.
- 자연어에서 추출한 접근성·연령·안전 조건은 사용자가 확인하기 전 확정 필터로 사용하지 않는다.
- 현재 자유 텍스트 hard constraint는 구조화·검수 전 자동 `pass/fail`로 실행하지 않는다.
- 빈 결과에서도 필수 조건을 자동 완화하지 않고, 사용자가 선택할 수 있는 완화안만 제시한다.

## 추천 공정성

- 광고, 제휴, 인기도, 편집 추천이 순위에 영향을 주면 구분할 수 있어야 한다.
- 특정 지역·가격대·유형·사업자만 반복 노출되는지 평가한다.
- 사용자는 추천 조건을 확인하고 수정하며 장소를 제외할 수 있어야 한다.
- 낮은 데이터 coverage를 낮은 장소 품질로 오인하거나, 알려진 장소만 반복 노출하지 않도록 추론 수준별 편차를 측정한다.

## 설명의 신뢰성

- 추천 이유는 실제 score component, 필터 판정과 evidence ID에서만 생성한다.
- 장소에 대한 근거 없는 장점, 운영 상태, 가격, 이동시간을 생성하지 않는다.
- 추정과 확인된 사실을 구분하고 `ai_draft`, 출처 등급, 확인일과 불확실성을 숨기지 않는다.
- 기존 장소 설명 전체를 추천 이유로 복사하지 않고 실제 요청에 기여한 특징만 사용한다.
- LLM이 문장을 다듬더라도 허용된 fact·수치·경고 밖의 내용을 추가하면 결과 생성을 실패시킨다.

## 변경 시 확인 사항

사용자 프로필, 위치, 행동 로그, 외부 AI 모델 또는 제휴 랭킹을 도입하는 SPEC에는 다음을 포함한다.

- 수집 필드와 목적
- 저장 위치, 접근 주체, 보관 기간, 삭제 방법
- 외부 전송 대상과 최소화 방법
- 사용자 고지와 제어 방식
- 오용·유출·잘못된 추천에 대한 폴백과 테스트
- AI 초안과 사람 승인 데이터의 분리·승격·철회 절차
