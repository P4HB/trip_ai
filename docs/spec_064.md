# SPEC-064: 추천 필수 조건 누락 방지 UI

- 상태: Implemented
- 작성일: 2026-08-31
- 최종 수정일: 2026-08-31
- 관련 요청: 현재 추천 UI가 필수 사항을 누락하기 쉽다는 베타 피드백을 검토하고 개선한다.
- 관련 문서: [문서 색인](README.md), [시스템 아키텍처](architecture.md), [SPEC-020](spec_020.md), [SPEC-062](spec_062.md)

- 선행 SPEC: SPEC-020, SPEC-062

## 배경

760px 이하 단일 스크롤 UI는 동행자, 날짜, 여행 방식, 취향과 확인 구간을 모두 펼치지만 단계 진행률을 숨긴다. 현재 화면에는 필수·선택 구분과 전체 완료 현황이 없고, 실행 버튼은 누락 개수를 알려주지 않는다. 또한 아무 날짜도 고르지 않은 상태가 확인 요약에서 `날짜 미정 → 날짜 미정`으로, 아무 취향도 고르지 않은 상태가 `취향 없이 골고루`로 표시되어 명시적으로 선택한 값처럼 보인다. 실행 뒤에는 첫 오류로 이동하지만 사용자는 실행 전에 무엇이 남았는지 파악하기 어렵다.

## 사실·결정·가정

- 사실: 현재 추천 실행에 필요한 응답 묶음은 동행, 날짜 또는 날짜 미정, 여행 지역, 찾는 장소, 이동수단, 여행 취향 또는 취향 없음의 6개다.
- 사실: `축제·행사(event)` 추천은 랭커가 여행 기간을 필수로 요구하지만 기존 UI validator는 날짜 미정을 통과시켜 마지막 알고리즘 오류로만 드러낸다.
- 사실: 추천 알고리즘은 기존 validator가 유효한 요청만 실행하도록 막고 있어 잘못된 요청이 랭커로 전달되지는 않는다.
- 결정: 필수 항목 6개와 고급 선택 항목을 화면에서 명시적으로 구분한다.
- 결정: 모바일은 완료 개수와 남은 항목을 항상 확인할 수 있게 하고, 하단 실행 버튼은 누락 개수를 알려주되 비활성화하지 않는다. 누르면 기존처럼 첫 누락 항목으로 이동한다.
- 결정: 확인 요약은 명시적으로 고르지 않은 날짜와 취향을 `미선택`으로 표시하고 누락 카드를 시각적으로 구분한다.
- 가정: 피드백은 최근 적용된 760px 이하 단일 스크롤 흐름을 중심으로 하며, 761px 이상 단계형 흐름은 기존 진행 차단을 유지하면서 필수·선택 표지만 함께 개선한다.
- 미결정 사항: 없음.

## 목표

- 사용자가 추천 실행 전에 어떤 입력이 필수인지와 몇 개가 남았는지 파악할 수 있게 한다.
- 선택 즉시 완료 현황, 구간 상태, 확인 요약과 실행 버튼 문구를 동기화한다.
- 누락 상태를 명시적 선택으로 오인하게 만드는 날짜·취향 요약을 바로잡는다.
- 누락된 채 실행하면 모든 누락 구간을 표시하고 첫 누락 입력으로 이동한다.
- 축제·행사를 선택했을 때 날짜가 추가로 필요하다는 교차 조건을 실행 전에 안내한다.
- 추천 알고리즘, 요청·결과 계약과 피드백 자동 저장 경계는 유지한다.

## 요구사항

- `REQ-6401`: 동행, 날짜, 여행 지역, 찾는 장소, 이동수단, 여행 취향의 6개 응답 묶음에 `필수` 표시와 `선택 전/완료/확인 필요` 상태를 제공해야 한다.
- `REQ-6402`: 추천 결과 설정, 필수 장소·확인 조건·제외 장소처럼 실행에 필요하지 않은 고급 입력에는 `선택` 표시를 제공해야 한다.
- `REQ-6403`: 모바일 상단 현황은 필수 조건 완료 개수, 진행 막대와 남은 항목 이름을 선택 즉시 갱신해야 한다.
- `REQ-6404`: 모바일 실행 버튼은 미완료 시 `필수 조건 N개 확인하기`, 첫 실행 준비 완료 시 `추천 결과 아래에서 보기`, 결과 생성 뒤에는 `이 조건으로 다시 추천받기`로 표시해야 하며 미완료 상태에서도 첫 오류 이동을 위해 사용할 수 있어야 한다.
- `REQ-6405`: 아무 날짜도 선택하지 않았거나 날짜 미정을 체크하지 않은 상태와, 프리셋·세부 취향·여행 MBTI를 모두 선택하지 않은 상태는 확인 요약에서 `미선택`으로 표시해야 한다.

> 후속 변경: 여행 취향의 프리셋·세부 취향·`none` 완료 경로는 [SPEC-065](spec_065.md)가 대체한다. 현재는 적용된 여행 MBTI 프로필만 여행 취향 완료로 계산한다.
- `REQ-6406`: 모바일 미완료 실행 시 모든 누락 구간과 확인 요약 누락 카드를 표시하고 기존 순서의 첫 누락 입력으로 이동해야 한다.
- `REQ-6407`: 값을 채우면 해당 오류·누락 표시가 즉시 해제되고 완료 개수·남은 항목·확인 요약·실행 버튼이 함께 갱신되어야 한다.
- `REQ-6408`: 761px 이상 단계형 validator, 모바일 단일 스크롤 배치, 요청·결과 계약과 추천·피드백 동작을 유지해야 한다.
- `REQ-6409`: 축제·행사를 선택하면 날짜 미정을 완료로 세지 않고 시작일·종료일을 요구해야 하며, 최종 실행은 viewport와 현재 단계에 관계없이 1~4단계를 다시 검증해야 한다.

## 입력과 출력

요청 필드와 필수 여부는 SPEC-020의 현재 계약을 유지한다. 이번 변경은 동일한 값을 읽는 표시·검증 피드백 계층만 추가한다.

| 응답 묶음 | 완료 조건 | 미선택 표시 |
|---|---|---|
| 동행 | `companionType`이 빈 문자열이 아님. `none`은 명시적 완료다. | 미선택 |
| 날짜 | 일반 목적은 날짜 미정 체크 또는 유효한 시작일·종료일. 축제·행사는 유효한 시작일·종료일만 완료 | 미선택 |
| 여행 지역 | `destinationRegion`이 빈 문자열이 아님 | 미선택 |
| 찾는 장소 | `intent`가 빈 문자열이 아님 | 미선택 |
| 이동수단 | `transportMode`가 빈 문자열이 아님 | 미선택 |
| 여행 취향 | `none` 프리셋 또는 원자 라벨 1개 이상. 적용된 여행 MBTI는 원자 라벨을 포함한다. | 미선택 |

## 설계

```text
입력 변경
  → 6개 필수 응답 상태 계산
  → 구간 상태 + 모바일 완료 현황 + 확인 요약 + 실행 버튼 동기화

모바일 미완료 실행
  → 누락 구간 전체 표시
  → 기존 단계 validator 순서로 첫 누락 항목 이동·포커스
  → 추천 미실행
```

- 상태 계산은 DOM과 현재 메모리 상태를 읽는 하나의 함수에서 수행한다.
- 모바일 완료 현황과 상태 문구는 `aria-live`를 사용하되 선택 카드의 기존 `aria-pressed` 계약을 유지한다.
- 실행 버튼을 disabled로 만들지 않아 오류 위치로 이동할 수 있게 한다.
- 확인 요약은 각 항목의 계산된 완료 여부를 사용해 누락 스타일과 수정 진입점을 함께 렌더링한다.

## 예외와 폴백

- 시작일만 있거나 종료일만 있거나 날짜 범위가 역전되면 날짜는 완료로 세지 않고 기존 날짜 오류를 표시한다.
- 축제·행사와 날짜 미정을 함께 선택하면 날짜 구간을 미완료로 표시하고 날짜 입력 안내로 이동한다.
- 세부 취향 행을 모두 지우면 취향은 다시 미완료가 된다.
- 760px을 초과하면 모바일 누락 강조는 제거하고 기존 단계별 오류 흐름을 유지한다.
- JavaScript 초기화 실패 시 기존 지도 로딩 오류 정책을 유지한다.

## 승인 기준

- `AC-6401`: 초기 390px 화면에서 필수 조건 `0 / 6 완료`, 여섯 남은 항목과 각 필수 표지가 보인다.
- `AC-6402`: 항목 선택마다 완료 개수, 상태, 남은 항목과 실행 버튼의 N이 즉시 줄어든다.
- `AC-6403`: 날짜와 취향을 명시적으로 고르기 전 확인 요약은 두 항목 모두 `미선택`으로 표시한다.
- `AC-6404`: 초기 실행 시 추천은 실행되지 않고 여섯 누락 구간·요약 카드가 표시되며 동행 구간으로 이동한다.
- `AC-6405`: 날짜 미정과 취향 없음은 각각 명시적으로 선택한 뒤 완료로 계산되고 요약에 그 선택이 표시된다.
- `AC-6406`: 6개 필수 조건을 모두 채우면 현황은 `6 / 6 완료`, 첫 실행 버튼은 `추천 결과 아래에서 보기`가 되고 기존 추천 결과가 생성되며 실행 뒤 버튼은 `이 조건으로 다시 추천받기`로 바뀐다.
- `AC-6407`: 761px 이상에서는 기존 5단계 진행·오류 차단·drawer 동작이 유지된다.
- `AC-6408`: 정적 dashboard, 앱 구문, 추천 알고리즘 회귀와 diff 검사가 통과한다.
- `AC-6409`: 축제·행사와 날짜 미정을 함께 선택하면 완료 수가 하나 줄고 날짜 필요 안내가 보이며, 모바일·데스크톱 최종 실행 모두 날짜 구간에서 차단된다.

## 구현 결과

- `map-ui/index.html`에 필수 6개 완료 현황, 각 입력의 필수·완료 상태, 고급 입력의 선택 표지와 축제 날짜 안내를 추가했다.
- `map-ui/app.js`에 하나의 필수 상태 계산 경계를 두고 모바일 완료 수·남은 항목·확인 요약·실행 버튼·구간 오류를 선택 즉시 동기화했다.
- 빈 날짜와 빈 취향은 확인 요약에서 `미선택`으로 표시하고, 명시적으로 날짜 미정 또는 취향 없음을 고른 경우에만 해당 선택 문구를 표시한다.
- 모바일 미완료 실행은 6개 누락 구간을 동시에 `aria-invalid`와 시각 상태로 표시하면서 기존 순서의 첫 누락 입력으로 이동한다.
- 축제·행사와 날짜 미정 조합을 UI validator에서 차단하고 날짜 구간으로 이동한다. 761px 이상 최종 실행도 1~4단계를 다시 검증한다.
- 완료 전·첫 실행 준비·결과 생성 뒤 CTA를 각각 `필수 조건 N개 확인하기`, `추천 결과 아래에서 보기`, `이 조건으로 다시 추천받기`로 구분하고 입력 변경 시 첫 실행 상태로 복원한다.
- 선택 카드는 색상 외에 접근성 이름에 포함되지 않는 장식 체크 표시를 추가하고 모바일 보조 문구 크기를 높였다. 고정 상단 오류는 sticky action 내부로 옮겨 질문 제목을 가리지 않게 했다.
- 날짜·세부 취향처럼 값을 직접 편집해 누락을 해소할 때도 이전 전역 오류 문구를 즉시 지우도록 입력 변경 경계를 통일했다.
- `scripts/validate_ccu_mmr_dashboard.cjs`에 필수 6개 DOM, 상태 동기화, 미선택 요약, 전체 누락, CTA와 축제 날짜·데스크톱 최종 재검증 계약을 추가했다.
- 390×844 브라우저에서 초기 `0 / 6`, 빈 실행의 누락·`aria-invalid` 각 6개, 선택별 감소, 축제·날짜 미정 `5 / 6`, 유효 날짜 뒤 `6 / 6`, 가로 overflow 없음과 일반 목적 10개 추천을 확인했다.

## 설계와 달라진 점

- 재현 중 축제·행사와 날짜 미정이 UI를 통과한 뒤 랭커에서만 실패하는 교차 조건을 발견해 REQ-6409와 viewport 공통 최종 재검증을 추가했다.

## 알려진 제한

- 실제 베타 사용자의 완료 시간·오류 재시도율은 분석 이벤트를 추가하지 않는 이번 범위에서 자동 측정하지 않는다.
- 선택 카드의 키보드 모델은 기존 `button` + `aria-pressed`를 유지한다. native radio 또는 roving `radiogroup` 전환은 별도 접근성 범위다.
- 브라우저 상호작용은 390×844와 1024px에서 수동 자동화로 검증했으며 저장소에는 실행형 DOM E2E 테스트 기반이 아직 없다.
- `node scripts/test_preference_elicitation.cjs`는 이번 변경과 무관하게 제거된 `travel-mbti-site/app/lib/preference-elicitation.js` snapshot을 마지막에 읽어 `ENOENT`로 실패한다. 같은 기준선 제한은 SPEC-058에도 기록되어 있으며 이번 범위의 `map-ui/preference-elicitation.js`는 변경하지 않았다.
