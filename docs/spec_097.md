# SPEC-097: 제출 비즈니스 프로세스 표기 통일과 설명 간소화

- 상태: Implemented
- 작성일: 2026-10-04
- 최종 수정일: 2026-10-04
- 관련 이슈: 사용자의 BP 표기 재확인 및 02 PDF 주석·부가 설명 제거 요청
- 관련 문서: [1단계 제출 Spec](../kaist_app/제출용/01_Trip_AI_1단계_Spec.md)
- 관련 코드: `kaist_app/_work/build_process.py`, `kaist_app/_work/render_process_pdf.py`
- 선행 SPEC: SPEC-094, SPEC-096

## 배경

현재 도면은 동일한 BP를 참여자별 세부 행동명으로 표시하고, 본문과 하단의 화면·요구사항 범위가 일부 다르다. 사용자는 표기를 확인한 뒤 02 PDF에서 주석과 부가 설명을 제거하도록 요청했다.

## 목표

- 제출 Spec §7.2의 BP-01~07 명칭을 도면에 동일하게 표시한다.
- 3장 도면을 참여자·업무·상호작용 중심으로 간소화한다.
- 편집 원본 drawio와 PDF를 동일한 내용으로 저장한다.

## 비목표

- 제출 Spec 본문 수정, 앱 기능·사업모델 변경, 제품 코드 구현

## 요구사항

- REQ-001: BP 이름은 제출 Spec의 정의를 읽어 사용하고 세부 행동은 별도 줄에 표시한다. BP-05에는 평가·정보 개선만 연결한다.
- REQ-002: 설명용 범례, 하단 해설, Spec 장 번호, REQ·T·E 참조, 예외 처리 분기를 제거한다. 제목·참여자·핵심 업무·화살표·화면 번호·쪽 번호를 남긴다.
- REQ-003: 전체 가치 교환, 여행 추천·일정·예약, 기업·기관 도입·운영의 3장 구성을 유지한다. 상품 조회 요청과 결과를 연결한다.
- REQ-004: 같은 정의에서 drawio·PDF를 재생성하고 모든 쪽을 렌더링해 확인한다.

## 입력과 출력

- 입력: 현재 제출 Spec §7, 기존 도면 생성 정의
- 출력: `kaist_app/제출용/02_Trip_AI_Business_Process.drawio`, `.pdf`
- 생성 중간 정의: `kaist_app/_work/process_scene.json`

## 설계

- 결정: 업무 제목의 BP 이름은 Spec을 기준으로 삼고, 사람·시스템별 작업은 두 번째 줄에 표시한다.
- 결정: 입력 검증·예외·상태 복구 대신 정상적인 사업·서비스 흐름을 도식화한다.
- 계획: 도면은 목표 서비스의 설계이며 이 수정으로 앱 기능의 구현 상태는 바뀌지 않는다.

## 예외와 폴백

이번 제출 도면에서 상세 예외 흐름은 생략한다. 제품의 처리 규칙은 변경하지 않는다.

## 영향 범위

- 도면 생성기, 중간 정의, PDF·drawio, 본 SPEC과 문서 색인
- 데이터 마이그레이션·개인정보 처리 변경 없음

## 승인 기준

- AC-001: 도면의 모든 BP 제목이 제출 Spec과 일치하고 평가·예약의 연결이 구분된다.
- AC-002: 설명용 주석·범례·참조 코드·예외 처리 분기가 제거되고 핵심 업무 흐름은 연결된다.
- AC-003: drawio·PDF 3장의 내용이 일치하고 연결선의 끝점이 유효하다. 전체 렌더에서 잘림·겹침이 없다.
- AC-004: 제출 Spec 본문은 수정되지 않는다.

## 구현 결과

- 도면 생성기가 제출 Spec §7.2에서 BP 이름을 읽도록 수정했다. 3장에 표시된 BP 제목 26개가 기준 이름과 모두 일치한다.
- 범례, 하단 가치·운영 해설, Spec·REQ·T·E 참조, 상세 예외 분기를 제거했다. 화면 번호와 핵심 업무·참여자·화살표는 유지했다.
- BP-05의 예약 문의 표현을 평가·정보 개선으로 정리했다. 상품 조회 요청·결과를 연결하고 예약·결제·변경·취소, 기업·기관 보고·지급·갱신 흐름을 정돈했다.
- drawio·PDF를 같은 정의에서 3장·48개 연결선으로 재생성했다. PDF와 drawio의 모든 표시 문구가 일치한다.
- AC-001·002: BP 26개 기준 명칭 일치, 제거 대상 문구 0개, 정상 흐름 연결 확인.
- AC-003: 연결선 48개 참조 확인, 무관한 업무 상자를 통과하는 선 0개, 선 라벨과 업무 상자 겹침 0개. 최종 PDF 3장을 2400px PNG로 렌더해 한글·잘림·배치를 확인했다.
- AC-004: 제출 Spec의 수정 전후 SHA-256 일치 확인.
- 검증 요약은 `kaist_app/_work/process_cleanup_20261004_validation.json`에 기록했다. 기존 도면·PDF·생성 정의는 `kaist_app/_work/before_process_cleanup_20261004/`에 보관했다.

검증 실행:

```powershell
python kaist_app/_work/build_process.py
python kaist_app/_work/render_process_pdf.py
pdftoppm -scale-to 2400 -png "kaist_app/제출용/02_Trip_AI_Business_Process.pdf" "kaist_app/_work/tmp/pdfs/process_cleanup_20261004/process"
```

Python·Poppler는 번들 런타임으로 실행했다. 별도 일회성 검증에서 PDF 텍스트·XML·BP 이름·연결선 좌표·원본 해시를 대조했다.
