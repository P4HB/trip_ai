# 추천 알고리즘

- 문서 상태: 목표 설계 초안, 미구현
- 최종 수정일: 2026-08-09

현재 코드에는 개인화 추천 알고리즘이 없다. 이 문서는 향후 기능 SPEC이 따라야 할 공통 구조와 불변조건을 정의한다. 구체적인 특징, 가중치, 모델, 임계값은 구현 SPEC과 평가 결과 없이 확정하지 않는다.

## 목표

- 사용자의 필수 조건을 위반하지 않는 후보를 제공한다.
- 취향 적합도뿐 아니라 거리, 시간, 예산, 다양성, 데이터 신뢰도를 함께 고려한다.
- 동일한 데이터·설정·입력에서는 재현 가능한 결과를 만든다.
- 각 결과가 선택된 실제 근거를 설명할 수 있게 한다.

## 단계별 파이프라인

### 1. 요청 정규화

- 날짜, 시간대, 인원, 이동수단, 예산 단위를 검증한다.
- 자연어 취향은 정규화된 태그 또는 특징으로 변환하되 원문도 추적 가능하게 둔다.
- 필수 제약과 선호 조건을 분리한다.

### 2. 후보 생성

- 대상 지역과 데이터 스냅샷에서 충분히 넓은 후보 집합을 만든다.
- 텍스트, 분류, 지리, 편집 추천 또는 임베딩 검색을 사용할 수 있지만 사용 경로를 기록한다.
- 한 검색 방식의 누락이 최종 결과 전체의 편향이 되지 않도록 후보 출처별 커버리지를 측정한다.

### 3. 필수 제약 필터

예시는 지역, 접근성, 확정된 영업 가능 시간, 이동 가능 거리, 명시적 제외 장소, 엄격한 예산 상한이다.

- 필수 제약 위반 후보는 높은 선호 점수로 복구하지 않는다.
- 데이터가 없다는 이유만으로 충족한다고 판단하지 않는다.
- 확인할 수 없는 제약은 제외, 사용자 확인 필요, 완화 제안 중 SPEC이 정한 폴백을 적용한다.

### 4. 특징 계산과 기본 랭킹

모든 특징은 방향과 범위를 명시하고 버전 관리한다. 기본 형태는 다음과 같다.

```text
base_score(place, request)
  = sum(weight_i * normalized_feature_i)
  - sum(penalty_j)

subject to:
  weight_i >= 0
  sum(weight_i) = 1
```

고려 가능한 특징군은 다음과 같다.

- 취향 및 동행 유형 적합도
- 이동시간 또는 거리 적합도
- 일정 문맥과 체류시간 적합도
- 예산 적합도
- 장소 품질과 데이터 신뢰도
- 신규성 또는 사용자의 과거 방문 이력
- 계절·날씨 문맥 적합도

특징이 누락되면 0점으로 단정하지 않는다. 중립값, 특징 제외 후 재정규화, 불확실성 패널티 중 하나를 SPEC에서 선택하고 평가한다.

### 5. 다양성 재정렬

상위 결과가 같은 카테고리나 인접 장소로만 채워지지 않도록 기본 점수 이후 별도 단계에서 다양성을 조정한다.

```text
rerank_score(candidate)
  = lambda * base_score(candidate)
  - (1 - lambda) * max_similarity(candidate, already_selected)
```

유사도에는 카테고리, 위치, 의미 태그를 사용할 수 있다. `lambda`와 최대 반복 허용 수는 평가를 포함한 SPEC에서 확정한다.

### 6. 일정과 동선 최적화

장소 추천과 방문 순서 결정을 분리한다. 일정 생성기는 다음을 고려한다.

- 사용 가능한 총 시간과 장소별 예상 체류시간
- 장소 간 이동시간과 이동수단
- 확인 가능한 영업시간과 예약 제약
- 식사·휴식 시간과 사용자의 속도 선호
- 날짜별 시작·종료 위치

경로를 계산할 수 없으면 직선거리 기반 추정임을 표시하거나 일정 생성을 생략한다. 추정값을 실제 이동시간처럼 표현하지 않는다.

### 7. 근거 기반 설명

- 가장 기여도가 큰 특징과 충족한 조건에서 추천 이유를 만든다.
- 필터링되지 않은 임의의 장소 설명을 추천 근거로 꾸미지 않는다.
- 변동 정보에는 기준 시각과 확인 필요 경고를 제공한다.
- 내부 원시 추론이 아니라 사용자에게 검증 가능한 요약 근거를 제공한다.

## 폴백 원칙

- 후보 없음: 어떤 필수 제약 때문에 비었는지 보여주고 완화 가능한 조건을 제안한다.
- 사용자 취향 없음: 지역·시간·데이터 신뢰도 기반의 비개인화 기준선을 사용하고 이를 표시한다.
- 운영정보 없음: 확인 필요 상태로 유지하고 시간 엄수 일정에는 사용하지 않는다.
- 외부 서비스 실패: 마지막 검증 스냅샷과 시각을 표시하거나 결과 생성을 중단한다.

## 버전과 재현성

추천 결과에는 최소한 다음 값을 연결한다.

- 장소 데이터 스냅샷
- 특징 정의 버전
- 가중치 또는 모델 버전
- 필터 정책 버전
- 경로 데이터 및 외부 문맥의 확인 시각

알고리즘 변경은 별도 SPEC과 [평가 전략](evaluation.md)의 회귀 결과를 필요로 한다.
