# SPEC-058: 추천 만족도 완료형 JSON 로그 저장

- 상태: Superseded
- 작성일: 2026-08-24
- 최종 수정일: 2026-08-24
- 관련 이슈:
- 관련 문서: [시스템 아키텍처](architecture.md), [데이터 계약](data_contracts.md), [안전 및 개인정보](safety_privacy.md), [SPEC-056](spec_056.md)
- 관련 코드: `map-ui/index.html`, `map-ui/styles.css`, `map-ui/app.js`, `map-ui/README.md`, `scripts/validate_ccu_mmr_dashboard.cjs`

## 배경

추천 목록과 일정 카드에는 장소별 1~5점 만족도와 최대 300자 의견 입력이 구현되어 있지만 값은 현재 탭 메모리에만 남는다. 사용자가 모든 추천 장소를 평가한 뒤 여행 조건과 추천 결과를 함께 보존할 명시적 동작이 없다. 현재 Map UI는 백엔드 없는 정적 사이트이므로 서버 저장을 도입하지 않고 사용자가 직접 관리할 수 있는 JSON 다운로드가 필요하다.

## 목표

- 현재 결과에 나타난 모든 고유 장소의 만족도 입력 완료 여부를 안내한다.
- 모든 만족도 입력이 끝난 뒤에만 활성화되는 저장 버튼을 제공한다.
- 사용자 선택, 여행 MBTI 상태, 추천·일정 결과, 장소별 점수와 의견을 하나의 버전된 JSON 로그로 다운로드한다.
- 저장 범위와 개인정보 경계를 UI와 기준 문서에 명시한다.

## 비목표

- 서버, 데이터베이스, 분석 서비스 또는 Web Storage로 로그를 자동 전송·저장하지 않는다.
- 로그인, 사용자 식별자, 여러 세션 병합, 운영 평가 대시보드를 구현하지 않는다.
- 자유 의견을 분석하거나 추천 랭킹에 재사용하지 않는다.
- 의견 입력을 필수로 만들지 않는다.

## 요구사항

- `REQ-5801`: 현재 추천 목록과 일자별 일정에 나타난 장소를 장소 ID 기준으로 중복 제거해 평가 대상을 계산한다.
- `REQ-5802`: 평가 대상마다 1~5점 중 하나를 선택해야 완료로 계산하며 자유 의견은 선택 사항이다.
- `REQ-5803`: 결과가 있을 때 완료 수와 전체 고유 장소 수를 표시하고, 모든 점수가 입력되기 전에는 저장 버튼을 비활성화한다.
- `REQ-5804`: 같은 장소가 추천 목록과 일정에 함께 나타나면 기존처럼 점수와 의견을 동기화하고 한 건으로 저장한다.
- `REQ-5805`: 활성화된 저장 버튼을 누르면 `travel-recommendation-feedback-log-v1` JSON 파일을 브라우저 다운로드로 생성한다.
- `REQ-5806`: 로그에는 내보내기 시각, 알고리즘·데이터 provenance, 구조화된 추천 요청과 단계형 사용자 선택, 여행 MBTI 질문·pair 응답·생성 및 적용 프로필, 현재 코스 variant 세션, 전체 추천·일정 결과를 포함한다.
- `REQ-5807`: 장소별 피드백에는 장소 ID·제목, 추천 순위 또는 일정 일차/역할 context, 점수·점수 라벨·의견을 포함한다.
- `REQ-5808`: 파일에는 저장 방식이 사용자 주도 브라우저 다운로드이며 서버 전송과 Web Storage 사용이 없음을 기록한다.
- `REQ-5809`: 새 추천 조건으로 결과가 초기화되면 완료 상태와 저장 버튼도 초기화한다.
- `REQ-5810`: 다운로드 파일 외의 영구 복사본은 만들지 않으며 파일 보관·삭제는 사용자 기기에서 사용자가 제어한다고 고지한다.

## 입력과 출력

- 입력: 현재 탭 메모리의 추천 요청·결과, 여행 MBTI 상태, variant 세션, 장소 ID별 `score: 1..5 | null`, `comment: string`(최대 300자).
- 필수 입력: 현재 결과에 나타난 모든 고유 장소의 정수 점수.
- 선택 입력: 장소별 의견.
- 출력: UTF-8 JSON 파일 `trip-ai-feedback-YYYYMMDD-HHMMSS.json`.
- 시각: `exported_at`은 UTC ISO 8601 문자열이다.
- 서버 출력: 없음.

## 설계

1. 추천 렌더링 뒤 추천 목록과 일정 장소를 순서대로 순회해 고유 장소 Map과 각 노출 context를 만든다.
2. 장소별 점수 변경 때 완료 수를 다시 계산한다. 전체 완료 전에는 버튼을 disabled 상태로 둔다.
3. 저장 시점에 현재 메모리 상태를 JSON 직렬화 가능한 snapshot으로 조립한다. 피드백은 고유 장소 한 건과 여러 context의 관계로 표현한다.
4. `Blob`과 object URL을 사용해 사용자가 명시적으로 파일을 내려받게 한다. 네트워크 요청, `localStorage`, `sessionStorage`, IndexedDB는 사용하지 않는다.

## 예외와 폴백

- 추천 결과나 평가 대상이 없으면 저장 패널을 숨긴다.
- 모든 점수가 완료되지 않은 상태에서는 로그를 만들거나 다운로드하지 않는다.
- 점수 상태가 예상 범위 밖이면 미완료로 취급한다.
- 브라우저 다운로드 생성이 실패하면 페이지 상태를 유지하고 실패 안내를 표시한다.

## 승인 기준

- `AC-5801`: 추천과 일정의 중복 장소를 한 번만 계산한 완료 수가 화면에 표시된다.
- `AC-5802`: 일부 점수만 입력하면 저장 버튼이 비활성이고 모든 고유 장소의 점수를 입력하면 활성화된다.
- `AC-5803`: 저장 버튼으로 내려받은 JSON이 v1 계약에 맞고 사용자 선택·MBTI·추천 결과·피드백을 포함한다.
- `AC-5804`: 같은 장소의 복수 노출 context와 동기화된 점수·의견이 한 피드백 항목에 보존된다.
- `AC-5805`: 기능 구현에 네트워크 전송과 Web Storage 영구 저장이 없고 사용자 고지가 보인다.
- `AC-5806`: 기존 추천·여행 MBTI 회귀 검증과 JavaScript 문법 검사가 통과한다.
- `AC-5807`: 데스크톱과 모바일 폭에서 완료 상태, 저장 버튼, 다운로드 동작을 브라우저로 확인한다.

## 구현 결과

- `map-ui/index.html`과 `map-ui/styles.css`에 평가 완료 수, 개인정보 고지, 완료 전 disabled 상태의 저장 버튼을 추가했다.
- `map-ui/app.js`가 추천·일정 장소를 ID 기준으로 중복 제거하고 점수 완료 상태를 동기화한다. 모든 점수 완료 시 사용자 선택·MBTI 상태·variant 세션·전체 추천 결과·context가 포함된 v1 JSON을 브라우저 다운로드로 생성한다.
- `docs/data_contracts.md`, `docs/architecture.md`, `docs/safety_privacy.md`, `map-ui/README.md`를 실제 저장·보관 경계에 맞게 갱신했다.
- 정적 검증에 DOM, 완료 계산, 스키마, 사용자 주도 다운로드, 네트워크·Web Storage 비사용 계약을 추가했다.
- 브라우저에서 10개 추천의 `0/10 → 10/10` 상태와 버튼 활성화, 자유 의견 입력, 실제 JSON 다운로드를 확인했다. 파일은 10개 entry, 요청·추천 결과, 점수·의견, `server_transmitted=false`, `web_storage_used=false`를 포함했다.
- 1일 일정 포함 결과에서는 피드백 카드 16개가 장소 ID 기준 15개 평가 대상으로 계산되어 중복 장소가 한 번만 완료 조건에 포함됨을 확인했다.
- 390×844 viewport에서 문서 가로 폭 390px, 저장 패널 320.59px, 버튼 290.59px로 가로 overflow가 없음을 확인했다.

## 알려진 제한

- 이 SPEC의 v1 브라우저 다운로드 동작은 SPEC-059의 v2 서버 적재 동작으로 대체됐다.
- 내려받은 파일은 사이트가 자동 회수·삭제하거나 여러 사용자의 로그로 집계하지 않는다.
- 운영 서버 저장, 동의·보관 기간·삭제 API가 필요한 평가 파이프라인은 별도 SPEC이 필요하다.
- `node scripts/test_preference_elicitation.cjs`는 현재 저장소에 테스트가 참조하는 `travel-mbti-site/app/lib/preference-elicitation.js`가 없어 `ENOENT`로 시작하지 못했다. `map-ui/preference-elicitation.js`를 직접 읽는 대시보드 검증과 CCU-MMR 회귀 검증은 통과했다.
