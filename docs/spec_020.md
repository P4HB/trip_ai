## 배경

현재 `map-ui`의 왼쪽 패널은 여행 맥락, 원자 라벨 선호, 출력 설정과 고급 조건을 하나의 긴 폼에 동시에 표시한다. 사용자는 추천을 받기 전에 작은 입력 컨트롤을 찾으며 긴 패널을 스크롤해야 하고, 다음에 무엇을 선택해야 하는지 안내받지 못한다. 또한 화면 초기화 시 예시값으로 추천이 자동 실행되어 베타 테스터가 자신이 입력한 조건이 반영되는 전환을 체감하기 어렵다.

## 목표

- 한 번에 하나의 논리 단계만 보여주는 여행 조건 입력 흐름을 제공한다.
- 동행자에서 시작해 날짜, 기본 여행 방식, 취향, 최종 확인 순서로 진행한다.
- 선택 내용을 마지막 확인 화면에서 요약하고 사용자의 명시적 실행 뒤에만 장소를 추천한다.
- 이전 단계로 돌아가 조건을 수정할 수 있고 데스크톱·모바일·키보드에서 같은 흐름을 완료할 수 있게 한다.
- 기존 CCU-MMR 점수, 코스 variant, 근사 일정, 지도와 고급 조건 기능을 유지한다.

## 요구사항

- `REQ-2001`: 추천 입력은 `동행자 → 날짜 → 여행 방식 → 여행 취향 → 확인` 5단계로 제공하고 현재 단계만 표시한다.
- `REQ-2002`: 현재 단계, 전체 단계 수와 완료 진행률을 시각적 텍스트로 표시한다.
- `REQ-2003`: 각 단계는 `이전`과 `다음`으로 이동하고, 필수 선택이 없거나 날짜 범위가 잘못되면 다음 단계로 이동하지 않고 해당 단계에 오류를 표시한다.
- `REQ-2004`: 동행자·지역·목적·이동수단·취향은 큰 선택 카드로 제공하고 기존 요청 값과 동기화한다.
- `REQ-2005`: 날짜 미정 선택 시 여행 기간을 비활성화해 `travelWindow=null`로 전달하며, 날짜를 입력하면 시작일과 종료일을 모두 요구한다.
- `REQ-2006`: 여행 방식 단계는 지역, 장소 목적과 제주 내 이동수단을 함께 선택하며 세 값이 모두 있어야 진행한다.
- `REQ-2007`: 여행 취향은 이해하기 쉬운 프리셋을 기본 선택지로 제공하고, 기존 원자 라벨 편집은 선택 단계 안의 상세 설정으로 유지한다.
- `REQ-2008`: 확인 단계는 동행자·기간·지역·목적·이동수단·취향을 사람이 읽을 수 있는 문구로 요약한다.
- `REQ-2009`: 추천은 확인 단계의 명시적 실행 전에는 자동 실행하지 않고 실행 뒤 기존 결과 패널·지도·일정에 반영한다.
- `REQ-2010`: 초기화는 추천 결과와 단계 상태를 지우고 첫 단계로 돌아가며 예시 추천을 자동 실행하지 않는다.
- `REQ-2011`: 고급 조건, 필수 장소, 제외 장소, 결과 수와 다양성 설정은 확인 단계에서 선택적으로 수정할 수 있다.
- `REQ-2012`: 내부 실험·AI 초안·변동 정보 재확인 고지는 유지하되 베타 사용자가 먼저 보는 제목과 안내는 여행자 언어로 표현한다.
- `REQ-2013`: 입력과 단계 상태는 기존처럼 브라우저 메모리에만 유지하고 Web Storage나 외부 서비스에 기록하지 않는다.

## 입력과 출력

추천 요청 스키마와 결과 스키마는 SPEC-017의 현재 구현을 유지한다. 단계 UI는 다음 필드를 기존 요청으로 변환하는 표시 계층이다.

```text
Step 1 동행자      -> companionType
Step 2 날짜        -> travelWindow | null
Step 3 여행 방식   -> destinationRegion, intent, transportMode
Step 4 여행 취향   -> preferences[]
Step 5 확인        -> resultCount, diversity, hardConstraints,
                       requiredPlaceIds, excludedPlaceIds
                       -> 명시적 rank 실행
```

정확한 위치, 자유 텍스트 취향, 개인 식별자는 입력받지 않는다. 날짜 시간대는 기존 `Asia/Seoul` 해석을 유지한다.

## 설계

```text
첫 단계
  -> 단계별 선택값 검증
  -> 다음 단계 / 이전 단계
  -> 마지막 확인 요약
  -> 장소 추천하기
  -> 기존 CCU-MMR rank
  -> 결과 패널 + 지도 + 근사 일정
```

- 단계 전환은 `map-ui/app.js`의 메모리 상태로 관리한다.
- 선택 카드는 기존 form control을 대체하는 새 데이터 계약이 아니라 동일 값을 동기화하는 표현 계층이다.
- 비활성 단계는 `hidden`과 `aria-hidden`을 함께 사용하고 단계 제목에 포커스를 이동한다.
- 추천 결과가 생긴 뒤 입력을 바꾸면 현재처럼 결과를 dirty 상태로 만들며 다시 마지막 실행이 필요하다.

## 예외와 폴백

- 동행자를 고르지 않으면 1단계에 머문다. 동행 점수를 사용하지 않는 명시적 선택은 `none`이다.
- 날짜 미정을 고르지 않은 상태에서 한쪽 날짜만 비어 있거나 시작일이 종료일보다 늦으면 2단계에 머문다.
- 취향 프리셋을 고르지 않아도 사용자가 원자 라벨을 하나 이상 직접 추가하면 진행할 수 있다. `취향 없이 추천`은 빈 `preferences[]`를 명시한다.
- 추천 실행 중 기존 랭커 검증 오류가 발생하면 확인 단계 오류 영역에 표시한다.
- JavaScript 초기화가 실패하면 기존 지도 로딩 오류를 표시한다.

## 승인 기준

- `AC-2001`: 초기 화면은 1/5 동행자 단계만 표시하고 추천 결과를 자동 생성하지 않는다.
- `AC-2002`: 동행자, 날짜, 여행 방식, 취향을 순서대로 선택해 5/5 확인 단계까지 이동할 수 있다.
- `AC-2003`: 각 단계에서 누락값·역전 날짜가 다음 진행을 막고 오류 문구와 해당 입력 포커스를 제공한다.
- `AC-2004`: 이전 버튼으로 돌아가 선택을 바꾸면 확인 요약과 최종 정규화 요청에 새 값이 반영된다.
- `AC-2005`: 날짜 미정은 일정 없는 장소 추천을 실행하고 유효한 날짜는 기존 근사 일정을 생성한다.
- `AC-2006`: 최종 실행 전 결과가 비어 있고, 실행 후 Top-N·코스 variant·일정·지도 마커가 기존 알고리즘 결과로 표시된다.
- `AC-2007`: 고급 조건·필수 장소·출력 설정과 기존 추천 결과 상세 기능이 유지된다.
- `AC-2008`: 1440px 데스크톱과 390px 모바일에서 단계 선택·이전·다음·최종 실행이 가로 넘침 없이 동작한다.
- `AC-2009`: 키보드로 선택 카드, 날짜, 이전·다음과 최종 실행에 접근할 수 있고 비활성 단계가 탭 순서에 들어오지 않는다.
- `AC-2010`: 기존 CCU-MMR 단위·대시보드 검증과 앱 구문 검사가 통과한다.

## 구현 결과

- `map-ui/index.html`을 동행자, 날짜, 여행 방식, 여행 취향, 조건 확인의 5단계 화면으로 재구성했다.
- 동행자·지역·목적·이동수단과 취향 프리셋을 큰 선택 카드로 제공하고 기존 요청 필드에 동기화했다.
- 단계 진행률, 이전·다음, 누락 선택과 날짜 범위 검증, 날짜 미정, 최종 사람이 읽을 수 있는 조건 요약과 단계별 수정 진입을 구현했다.
- 마지막 실행 전 자동 추천을 제거하고 최종 실행 뒤에만 기존 Top-N, 코스 variant, 근사 일정과 지도 마커를 표시한다.
- 기존 원자 라벨 직접 편집, 결과 설정, 필수 장소·확인 조건·제외 장소와 내부 trace 패널은 선택형 상세 설정으로 유지했다.
- 데스크톱 기본 viewport와 390×844 모바일 drawer에서 가로 넘침 없이 첫 단계를 확인했고, 날짜 미정 장소 추천과 3일 날짜 입력 일정 추천을 각각 브라우저에서 완료했다.
- `scripts/validate_ccu_mmr_dashboard.cjs`에 5단계 DOM, 카드-요청 필드 연결, 단계 검증과 초기 자동 실행 금지 회귀 검사를 추가했다.
