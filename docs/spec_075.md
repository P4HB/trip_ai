# SPEC-075: 하루 유형 상한을 위한 기존 지도 장소 대표 유형 분류

- 상태: Implemented
- 작성일: 2026-09-11
- 최종 수정일: 2026-09-11
- 관련 요청: 기존 지도 장소 2,153곳을 산·오름/카페/박물관/정원 등으로 분류한다.
- 관련 문서: [색인](README.md), [데이터 계약](data_contracts.md), [SPEC-002](spec_002.md)
- 관련 코드: `scripts/classify_place_types.py`, `config/place_type_taxonomy.v1.json`

## 배경

현재 CCU-MMR의 연속 선호 라벨은 하루 동일 경험 횟수를 집계하기 위한 범주가 아니다. 사용자는 먼저 기존 지도 장소 2,153곳의 분류를 요청하고 신규 카카오 후보는 제외했다.

## 목표

- 모든 대상 장소에 대표 유형 하나와 근거·검토 상태를 가진 독립 분류 sidecar를 제공한다.
- TourAPI 신분류 코드와 기존 조사 근거를 사용하고, 이름의 부분문자열만으로 카페·숙소를 산/정원 등으로 오분류하지 않는다.
- 향후 하루 상한에서 사용할 안정적인 유형 ID를 정의한다.

## 비목표

- 하루 상한 수치 결정·추천 엔진 적용·배포, 기존 41축 재라벨링, 신규 카카오 2,374건 분류.
- 운영 원본 DB/지도 번들 수정, 섬 단위 계층형 추천, 최신 영업 상태 확인.

## 요구사항

- REQ-001: 현재 `map-ui/data/jeju-places.js`의 2,153개 ID와 정확히 일치해야 한다. 원본 2,154건 중 지도 제외 ID는 포함하지 않는다.
- REQ-002: 대표 유형은 taxonomy에 정의된 값 하나다. 불명확하면 `unknown`과 `needs_review`를 사용한다.
- REQ-003: 원본 `lclsSystm1/2/3`, content type, 적용 규칙 ID, 근거와 기존 조사 출처를 보존한다. 자동 분류는 사람 확정으로 표시하지 않는다.
- REQ-004: 세부 코드 규칙을 기본으로 하고, 복합 코드의 예외는 ID별 근거 있는 보정으로 관리한다. 코드 불일치·부족 근거를 검토 큐에 남긴다.
- REQ-005: JSONL과 별도 SQLite, 사람이 읽을 수 있는 분포·검토 보고서를 생성한다. 원본 데이터·라벨·지도·추천 동작은 변경하지 않는다.
- REQ-006: 동일 입력과 taxonomy에서 재실행 결과가 같아야 한다. 입력 해시와 버전을 기록한다.

## 입력과 출력

입력: 지도 번들, `data/tourapi/jeju/2026-08-09/jeju_places.json`, taxonomy 설정. 지도 좌표는 경도(lng)·위도(lat) 순서를 유지한다. 사용자 정보는 읽지 않는다.

출력: `data/labeling/jeju/2026-09-11/place-types-v1/`의 `place_types.jsonl`, `place_types.sqlite3`, `review_queue.jsonl`, `report.md`, `manifest.json`.

## 설계

구현: 원본 ID와 지도 ID 조인 → 명시적 코드 매핑 → 조사 기반 ID 예외 보정 → 유형/근거/상태 생성 → JSONL·SQLite·검토 보고서. 대표 유형 하나만 횟수 집계에 사용하도록 설계하며, 동일 섬 내 관계나 보조 태그는 이번에 추가하지 않는다. 도보 코스와 해안 감상 등 복합 경험은 대표 경험 기준으로 분류하고 경계 사례를 검토 대상으로 표시한다. 불확실한 라벨 confidence를 임의의 확률로 만들지 않는다.

## 예외와 폴백

중복 ID·입력 누락·미등록 taxonomy 참조는 실패한다. 분류 근거가 없으면 unknown으로 남긴다. 복합 장소는 검토 상태를 유지하며 unknown을 이후 상한 우회 수단으로 사용하면 안 된다(상한 정책은 미구현).

## 영향 범위

새 스크립트·설정·독립 분류 DB와 문서 추가. 원본 DB 마이그레이션 및 사용자 동작 변경 없음.

## 승인 기준

- AC-001: 대상 2,153개 고유 ID가 정확히 한 번씩 출력되고 추천 준비 1,663곳/그 외 490곳도 별도 집계된다.
- AC-002: 모든 대표 유형이 유효하고 근거와 규칙 ID가 있으며 unknown은 검토 큐에 있다.
- AC-003: 산·오름/카페/박물관/정원 및 코드 경계 사례를 검증한다. 식당·숙박 이름 속 자연 키워드는 유형을 덮어쓰지 않는다.
- AC-004: SQLite 무결성과 JSONL 값 일치, 재생성 해시 일치, 기존 입력 해시 불변을 확인한다.

## 구현 결과

아래 건수는 최초 생성 시점의 기록이다. 사용자 확정 19곳·경관·걷기 추가 이후 현재 동작과 건수는 [SPEC-076](spec_076.md)을 따른다.

- `config/place_type_taxonomy.v1.json`: 32개 대표 유형과 unknown, 원본 세부 코드·접두사 규칙, 117개 ID별 근거 보정. 명칭 판정은 자연 키워드를 전체 검색하지 않고 특정 코드 안에서 근거를 확인한 ID별 결정으로 저장한다.
- `scripts/classify_place_types.py`: 2,153곳 분류, 추천 준비 여부·규칙·근거·기존 조사 출처, JSONL·별도 SQLite·보고서·manifest 생성. 원본 DB와 지도 번들은 변경하지 않는다.
- 결과: 2,153곳(추천 준비 1,663/그 외 490), 미분류 0, `rule_classified` 2,126, `needs_review` 27. 자동 규칙 판정도 사람 확정은 아니다.
- 주요 분포: 산·오름 94, 해변·해안 115, 숲 24, 정원 36, 박물관·미술관·전시 79, 카페·찻집·베이커리 243(추천 준비 232).
- `report.md`에 전체 장소와 검토 27곳을 함께 기록한다. `review_queue.jsonl`에는 근거와 출처까지 포함한다.

## 검증 결과

- `python -m py_compile scripts/classify_place_types.py scripts/test_place_types.py`: 통과.
- `python scripts/test_place_types.py`: AC-001~004 통과. 2,153 고유 ID/1,663 추천 준비, 지도 제외 영주산 미포함, 대표 장소와 이름 키워드 오염 방지 fixture, unknown 폴백, 검토 큐, SQLite integrity 및 전 레코드 JSONL 일치, 재생성 파일 해시 동일, 원본·지도·엔진·원본 SQLite 해시 불변을 확인했다.
- 이 검증은 분류 정답률이나 추천 만족도 향상을 의미하지 않는다. 27개 경계 사례의 사용자/사람 검수와 하루 상한 적용은 후속 범위다.
