# 제주 여행 추천 베타

날짜 단계에서는 실제 출발일·돌아오는 날 대신 1박 2일·2박 3일·3박 4일 기간만 고를 수도 있습니다. 기간만 선택하면 월별 점수 없이 선택한 일수만큼 날짜가 없는 근사 일정을 만들며, 축제·행사는 실제 날짜를 입력해야 합니다.

프레임워크 없이 실행되는 정적 HTML 추천 UI입니다. 사용자는 동행자, 날짜, 여행 방식, 여행 MBTI, 조건 확인을 완료한 뒤 장소 추천을 실행합니다. 1,240px 초과 데스크톱에서는 왼쪽 선택 패널 우측 상단의 `접기`로 지도를 넓히고, 지도 왼쪽의 `선택지 펼치기`로 원래 3열을 복원할 수 있습니다. 입력값은 유지되며 접힘 상태는 새로고침 뒤 저장하지 않습니다. 장소 상세 대표 이미지는 원본 비율 전체를 표시하고 사진 버튼을 누르면 큰 이미지 뷰어가 열립니다. 원본이 작으면 과도하게 확대하지 않고 누락·실패 시 placeholder를 표시합니다. 760px 이하 모바일에서는 다섯 선택 구간을 한 세로 페이지에 모두 펼치고, 필수 6개 조건의 완료 수·남은 항목과 누락 위치를 실시간으로 보여줍니다. 실행한 추천 장소·일정은 입력 바로 아래에 이어지며 지도는 그다음에 표시됩니다. 761px 이상에서는 기존 5단계 흐름과 태블릿 drawer를 유지하되 최종 실행 전에 전체 필수 조건을 다시 검증합니다. 축제·행사는 날짜 미정을 사용할 수 없고 유효한 출발일·돌아오는 날이 필요합니다. 취향 구간은 프리셋·취향 없음·수동 세부 조정 없이 여행 MBTI 검사만 제공하며 결과 프로필을 적용해야 완료됩니다. A/R·O/I·L/H 축마다 6개씩 총 18개 상황 질문과 최대 3개 적응형 가상 장소 비교에서 A·B·둘 다 좋음·둘 다 싫음을 고를 수 있습니다. 양쪽 응답은 유형 축에는 중립이고 두 장면의 평균 feature를 약한 긍정 또는 회피 신호로 반영합니다. 같은 profile을 3축 8개 여행 MBTI로 요약하며, 결과를 적용해도 추천은 자동 실행하지 않고 마지막 명시적 실행 뒤에만 계산합니다.

한국관광공사 TourAPI 제주 장소 2,154건 중 정상 좌표 2,153건을 표시하며, 24개 취향 라벨과 Companion 5개·Month 12개가 모두 있는 1,663곳을 `ccu-mmr-v6-travel-mbti-three-axis`로 추천합니다. 여행 MBTI 유형 문자는 표시·공유 전용이고 실제 추천에는 최대 8개 active feature의 연속 weight만 사용합니다. `balanced` 모드는 관련도 상위 1·2·3위 seed 코스 3안 중 하나를 고르고 `다른 코스 보기`는 아직 안 본 코스를 우선합니다. 장소 상세는 동일 출처 리뷰 API를 지연 호출해 승인된 Kakao 교차 매칭과 연결된 수집 후기 최대 5건을 표시합니다. 작성자명은 DB·API·화면에서 제외하고 수집 시점과 Kakao 원문 링크를 함께 제공합니다. 추천 결과 최상단에서 30자 이내 이름 또는 별칭을 받고, 추천 목록과 일정의 같은 장소는 1~5 만족도와 최대 300자 의견을 즉시 동기화합니다. 이름 또는 별칭이 입력된 상태에서 만족도를 선택하면 즉시, 의견은 마지막 입력 후 800ms에 여행 조건·MBTI 상태·추천/일정 결과·모든 장소의 현재 피드백을 `travel-recommendation-feedback-log-v3`로 `/travel/api/feedback`에 자동 전송합니다. 이름만 입력하거나 이름 없이 평가한 상태에서는 전송하지 않습니다. 서버는 사용자가 입력한 이름 또는 별칭을 포함한 추천 세션별 최신 스냅샷 한 행을 전용 SQLite에 90일 보관하며 연락처·현재 위치·IP는 저장하지 않습니다. Web Storage는 사용하지 않습니다.

여행 시작일·종료일과 자차 여부를 입력하고 장소명·주소·ID 검색 결과에서 필수 장소를 선택하면 근사 일정을 함께 만듭니다. 자차는 중심 반경 15km, 비자차는 5km를 사용하며 하루 capacity는 최대 6곳입니다. 필수 군집과 사용자가 고른 중심을 먼저 보존하고 남은 일자는 현재 코스 Top-N의 반경 밖 장소를 자동 중심으로 채우므로 코스를 바꾸면 일정도 함께 다시 계산됩니다. 오른쪽 일차 카드에 마우스를 올리거나 키보드 포커스를 두면 지도에는 해당 일차 장소만 강조되고, 벗어나면 전체 일정이 복원됩니다.

## 실행

저장소 루트에서 다음 명령을 실행합니다.

```powershell
python -m http.server 8080 -d map-ui
```

그다음 <http://localhost:8080>을 엽니다. 이 단순 정적 서버에서는 리뷰 API가 없으므로 후기 섹션은 오류 폴백을 표시합니다. 리뷰까지 로컬 확인하려면 `server/travel-feedback` API와 `/travel/api/` 프록시를 함께 실행해야 합니다. 지도 타일과 장소 이미지는 인터넷 연결이 필요합니다.

## Vercel 배포와 기존 DB 연결

Vercel 프로젝트의 Root Directory는 `map-ui`, Framework Preset은 `Other`이며 별도 빌드 없이 이 폴더를 제공한다. 공개 주소는 `https://trip-ai-wine-eight.vercel.app/`다. `vercel.json`이 `POST /travel/api/feedback`과 숫자 ID의 `GET /api/places/{contentid}/reviews`를 기존 `https://168-107-40-231.sslip.io/travel/api/`로 전달한다. 평가 로그는 Vercel DB가 아닌 기존 서버의 같은 SQLite에 저장된다.

평가 POST의 Origin이 공개 Vercel 주소에 정확히 일치할 때만 기존 서버 Origin으로 변환한다. 다른 Origin은 그대로 전달해 기존 API의 거부 정책을 유지한다. Preview 주소는 평가 저장 허용 대상이 아니며 공개 도메인을 바꾸면 이 설정도 갱신해야 한다. 피드백 응답은 캐시하지 않고 기존 저장 성공·오류·재시도 흐름을 사용한다. 친구 서버가 중단되면 Vercel에서도 저장과 후기 조회가 실패한다.

배포 후 `python3 scripts/check_vercel_feedback_proxy.py`로 정적 자산·후기·거부 정책을 확인한다. `--write-test`를 붙이면 `DEPLOYMENT-TEST-SPEC081` 이름의 합성 세션 **1개를 실제 DB에 저장**해 두 주소의 세션 생성·수정·중복 영수증을 교차 검증한다. 이 행은 기존 90일 보존 대상이며 실제 테스터 분석에서 제외한다. 상세 결정·검증 결과는 [SPEC-081](../docs/spec_081.md)을 따른다.

## 데이터 갱신

현재 데모는 TourAPI와 라벨 snapshot이 모두 `2026-08-09`일 때만 번들을 만듭니다. 원본·라벨을 갱신한 뒤 날짜 상수와 계약을 함께 검토하고 다음 스크립트를 실행합니다.

```powershell
node scripts/build_map_ui_data.mjs
```

지도 라이브러리는 `vendor` 폴더에 포함되어 있으며 실행 시 npm이나 별도의 로그인은 필요하지 않습니다.

```powershell
node scripts/test_preference_elicitation.cjs
node scripts/test_ccu_mmr.cjs
node scripts/validate_ccu_mmr_dashboard.cjs
python scripts/validate_kakao_review_db.py
python -m unittest server/travel-feedback/test_feedback_api.py
```

이 화면은 `ai_draft` 내부 비교용입니다. 웹 조사 문장도 AI 초안이므로 운영시간·가격·휴무·행사 일정은 연결된 원문에서 다시 확인해야 합니다. 일정 군집은 실제 도로·대중교통 이동시간이 아니라 중심과 장소 사이의 Haversine 직선거리만 사용합니다. 날씨·영업·예약·접근성·이동시간·가격을 보장하지 않습니다. 사용자 입력과 여행 MBTI 프로필은 평가 전까지 브라우저 메모리에만 남고, 이름 또는 별칭과 만족도 또는 의견이 모두 준비되면 추천 세션의 최신 평가 스냅샷과 함께 서버에 자동 전송되어 90일간 저장됩니다. 공유 문구에는 유형 코드·이름·공개 설명만 포함합니다.

## 날짜 기반 동선 (SPEC-083)

실제 출발일·종료일로 자동차 장소 추천을 실행하면 별도 ‘시간표 있는 동선’ 영역에서 날짜마다 공개 출발/종료 장소와 활동 시각을 지정할 수 있다. 점심·저녁 창과 식사 길이·식당 추가 이동 허용 분은 수정 가능하며 날짜별로 자동 포함/반드시 포함/제외를 선택한다. 자동 포함은 활동 시간 밖의 식사를 생략 사유와 함께 표시한다. 날짜 미정·기간만 선택·비자동차는 기존 장소 추천을 유지하고 동선 생성을 차단한다. 최대 7일을 하루씩 순차 요청하고 완료된 날짜부터 표시한다.

`itinerary.js`는 Top-N 대신 `schedule.dayClusters`의 모든 날짜별 후보·필수·anchor를 전송한다. 동선 응답은 원래 추천 결과/평가 세션과 분리해 렌더링하고 날짜·추천·동선 조건 변경 시 취소·무효화한다. 이전 응답은 요청 ID와 revision을 확인해 무시한다. 식당은 미선정이며 슬롯의 앞뒤 위치·경로·우회 여유만 준비한다.

실패한 날짜에도 사유가 남고 다른 날짜의 성공은 보존한다. `generation_failed`는 모델이 제한된 시도 안에 조건을 만족하는 시간표를 찾지 못한 상태로 표시한다. 날짜/옵션 변경은 이후 요청을 중단한다. 다시 만들기는 전체 날짜를 재요청하며 완료된 날짜만 고정한 부분 재시도는 아직 제공하지 않는다.

`vercel.json`은 `POST /travel/api/itineraries`도 기존 서버로 전달한다. 기능은 서버의 `ITINERARY_ENABLED`와 서버 키·공개 데이터 준비가 필요하다. [서버 설정](../server/travel-feedback/README.md#날짜-기반-동선-spec-083), [검증·알려진 제한](../docs/spec_083.md#구현-결과)을 확인한다. 단순 정적 로컬 서버에서는 API가 없으므로 실패 안내와 기존 추천 유지까지 확인할 수 있다.
